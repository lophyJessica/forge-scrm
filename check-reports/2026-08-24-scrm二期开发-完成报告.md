### 与《核心字段清单》的差异说明

1. **开发方案检查清单里写的是「16 张表」，实际建了 17 张**。逐条比对字段清单的 MVP 必建表后确认：
   字段清单实际列出的一期必建实体正好是上表 17 个，方案里的 16 为约数笔误，**没有多建也没有少建**。
2. **未建的 3 张表均为字段清单明确标注「不作为 MVP 必建表」**：
   - `prompt_version`（⚠️ 待确认扩展实体）——一期改为 `prompt_template.version` 自增 + 在
     `topic` / `script` / `analysis_task` 上落 `prompt_version_snapshot` JSON 快照实现追溯，满足 S04；
   - `topic_version`（D8 已确认二期评估，一期不建表）；
   - `material_version`（⚠️ 待确认扩展实体，MVP 不建）。
3. **枚举落库方式**：为兼容 SQLite 与 MySQL，枚举以字符串列存中文值（`values_callable`），
   应用层用 `StrEnum` 强校验，DDL 仍按 MySQL 标准（`utf8mb4`、显式长度）。
4. **索引**：按字段清单在状态、分类、批次号、外键、创建时间等查询热点建立索引，随初始迁移一并创建。

### 需人工确认（未新增枚举，仅标注）

- `analysis_task.task_type` 一期取值为「资料分析 / 数据分析」。context/05 §4.7 只描述了分析任务的存在，
  **未枚举任务类型**。此二值是按模块 04 上下文推定的最小集合，代码内已加 `TODO 需人工确认` 注释，
  **请调研者确认是否就是这两类**；如需调整，改 `app/core/enums.py` 一处即可，前端自动跟随（枚举走 `/api/meta/enums`）。

## 六、本地启动说明

### 后端

```bash
cd backend
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env          # 至少填 JWT_SECRET 与 DEEPSEEK_API_KEY
.venv/bin/alembic upgrade head
.venv/bin/uvicorn app.main:app --reload --port 8000
```

- API：<http://127.0.0.1:8000/api>　文档：<http://127.0.0.1:8000/docs>
- 首次启动自动创建管理员 **admin / admin123** 与 6 个资料分类（幂等），登录后请立即改密。

### 前端

```bash
cd frontend
npm install
npm run dev     # http://localhost:5173，已代理 /api → 127.0.0.1:8000
npm run build   # 生产构建，产物在 dist/
```

### 自测

```bash
cd backend
.venv/bin/python scripts/selftest_mvp.py
```

后重跑 `alembic upgrade head` 即可，驱动 `PyMySQL` 已在依赖内。详见 `backend/README.md` 第 5 节。
