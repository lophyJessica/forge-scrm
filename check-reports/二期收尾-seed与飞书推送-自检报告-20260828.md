## 三、每个文件改动点

### 3.1 `backend/app/core/config.py`

- 增加 `feishu_app_id`、`feishu_app_secret`、`feishu_push_open_ids`。
- 配置由现有 `BaseSettings` 机制从 `FEISHU_APP_ID`、`FEISHU_APP_SECRET`、`FEISHU_PUSH_OPEN_IDS` 环境变量读取。
- 未写入任何真实 App Secret、token 或接收人标识。

### 3.2 `backend/app/services/seed.py`

- 新增 `seed_builtin_templates(db)`，遍历全部 `PromptTaskType` 枚举。
- 以“相同 task_type 且名称以‘内置’开头”判断模板是否已存在；存在即跳过，不覆盖用户修改。
- 缺失时补建 `内置{任务类型}提示词`，状态为启用、版本为 1、创建人为种子管理员。
- 选题、脚本分别使用对应 service 默认提示词；资料分析和数据分析沿用分析 service 默认提示词。
- 只记录本次实际补建的模板名；`run_seed()` 已接入该步骤。

### 3.3 `backend/app/services/feishu_push.py`

- `get_tenant_token()` 调用飞书企业自建应用 tenant token 接口，HTTP 超时为 10 秒。
- token 仅缓存在当前进程内，并在过期前 5 分钟刷新。
- `send_report_card()` 使用 `receive_id_type=open_id` 发送互动卡片；摘要最多保留 800 字。
- 飞书返回 `99991663` 或 `99991661` 时强制刷新 token，并且只重试一次。
- 对外只返回 HTTP 状态、飞书 code/msg 和可选 message_id；网络异常转换为不含请求头和凭据的摘要。
- provider 消息中的 App Secret 或缓存 token 会被脱敏，避免进入异常、数据库记录或日志。

### 3.4 `backend/app/routers/reports.py`

- 执行接口不再返回 501，当前仅支持飞书渠道，未实现微信。
- 缺少任一飞书必需配置时，任务回到“待推送”，并返回明确的管理员配置提示。
- 从逗号分隔的 `FEISHU_PUSH_OPEN_IDS` 读取多个接收人，逐个发送并逐人写入 `ReportPushRecord`。
- 全部发送成功时任务置“已推送”；任一失败时任务置“失败”。
- 失败任务手动重试时沿用原有 `retry_count + 1` 行为。
- 推送记录只保存接收人 open_id、结果、飞书 code/msg 摘要和可选 message_id，不保存 Secret、token 或 Authorization 请求头。

## 五、遗留风险

1. 本地没有使用真实飞书凭据发起线上请求；已完成 mock 协议测试，生产环境仍需用运维配置做一次端到端验收。
2. token 为进程内缓存；多 worker 部署时每个 worker 各自维护缓存，这是无共享缓存依赖下的预期行为。
3. 本期按 PRD v2 使用 `open_id`，不实现 user_id/open_id 查询或通讯录映射；环境变量必须配置有效 open_id。
4. 当前接口同步逐个发送，多接收人时总耗时随人数增长，并受单次 10 秒 HTTP 超时约束；本期未扩展后台队列。
5. 微信推送、群 ID 获取、定时生成和 APScheduler 均按范围明确不实现。
