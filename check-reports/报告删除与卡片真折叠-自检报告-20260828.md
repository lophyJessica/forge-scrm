## 卡片 2.0 查证结论

- 项目虚拟环境未安装 `lark_oapi` 或 `lark`，现有飞书集成使用 `httpx` 直接调用开放平台接口，因此没有可复用的本地 SDK 卡片构造器或版本号。
- 查证依据：飞书开放平台官方文档《折叠面板》：<https://open.feishu.cn/document/feishu-cards/card-json-v2-components/containers/collapsible-panel>，页面显示最后更新于 2024-12-31。
- 官方 Card JSON 2.0 要求顶层声明 `schema: "2.0"`；折叠面板组件使用 `tag: "collapsible_panel"`，支持 `expanded`、`direction`、`vertical_spacing`、`padding`、`background_color`、`header`、`border`、`elements` 等字段。
- 本次采用保守白名单字段，不使用未经确认的 `actions` 等扩展字段。面板内正文使用 2.0 的 `markdown` 组件，`expanded: false` 明确默认收起。

## 改动文件

### `backend/app/routers/reports.py`

- 新增 `DELETE /api/reports/{report_id}`，权限使用 `Permission.报告推送`。
- 生成中报告拒绝删除；存在任意推送任务时返回“该报告已有推送记录，为保持对账完整不可删除”；其余报告由 ORM 删除并提交。
- 飞书发送调用改为读取结构化 `PushResult`；发生 2.0 降级时，仅在对应推送记录的 `message_summary` 追加“卡片2.0降级”。

### `backend/app/services/feishu_push.py`

- 新增 Card JSON 2.0 构造：紫色标题、生成时间、摘要、数据概览及默认收起的 `collapsible_panel` 正文。
- 保留 28KB 上限，使用二分截断正文并追加超长提示；短正文完整放入折叠面板。
- 保留旧版 500 字平铺卡片作为兼容降级，不再作为默认卡片。
- 发送流程拆分为卡片版本降级与 token 刷新两层：每个卡片版本各自保留一次 token 失效刷新；仅 HTTP 400 或明确组件不支持码 `99991672` 触发一次旧版降级；网络、服务端及鉴权错误不误触发降级。
- 返回结构化结果，供路由记录是否发生降级；响应摘要仍执行既有凭据脱敏。

### `frontend/src/pages/reports/ReportList.tsx`

- 非“生成中”报告的操作列新增 `link + small + danger` 删除按钮。
- 删除前使用 `Modal.confirm` 展示“确认删除该报告？删除后不可恢复”；成功后刷新当前列表页。

### `frontend/src/pages/reports/ReportDetail.tsx`

- 非“生成中”报告的页头操作区新增 danger 链接删除按钮。
- 删除前二次确认；成功后返回 `/reports`。
