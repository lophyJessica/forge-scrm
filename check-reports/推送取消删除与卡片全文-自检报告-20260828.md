## 三、每个文件改动点

### 3.1 `backend/app/models/report.py`

- `ReportPushStatus` 增加终态“已取消”。
- `report_push_task.status` 与 `report_push_record.status` 共用该 Python 枚举，因此两列模型口径同步更新。

### 3.2 `backend/app/routers/reports.py`

- 新增 `POST /api/reports/push-tasks/{task_id}/cancel`。
- 仅待推送、失败任务可取消；其余状态返回业务错误。
- 新增 `DELETE /api/reports/push-tasks/{task_id}`。
- 推送中任务返回“推送执行中，请稍后再试”；其余状态删除任务，关联 records 由现有 ORM 与数据库级联规则删除。
- 执行接口新增已取消终态保护，防止绕过前端再次发送。
- 使用报告已有类型、周期、`source_snapshot.sources` 数量组装数据概览。
- 调用飞书发送服务时传入 `report.content` 正文，不增加报告字段。

### 3.3 `backend/app/services/feishu_push.py`

- `send_report_card()` 增加 `report_body` 参数，并支持可选数据概览。
- 卡片保留标题、生成时间和最多 800 字摘要，增加数据概览与报告正文两个基础 `lark_md` 区块。
- 项目未安装 `lark_oapi`，也没有可确认的折叠组件常量，因此按 PRD 兜底方案使用平铺正文，不臆造 collapsible panel。
- 轻量转换 Markdown 标题为粗体，将表格行转为列表并跳过表格分隔行；不引入复杂解析器或新依赖。
- 按 UTF-8 序列化后的卡片 JSON 字节数做二分截断，严格保持小于 28KB。
- 超限正文末尾追加“正文超长已截断，完整内容请登录系统查看”，不增加跳转按钮。

### 3.4 `backend/alembic/versions/f2a8c4d91e70_add_cancelled_push_status.py`

- 当前 `enum_type` 使用 `SAEnum(native_enum=True)`，MySQL 为原生 ENUM，因此迁移必需。
- upgrade 扩展 `report_push_task.status` 与 `report_push_record.status`，增加“已取消”。
- downgrade 先把已取消任务恢复为待推送，再缩减 ENUM，避免降级时出现非法枚举值。
- 新迁移 head：`f2a8c4d91e70`。
- 按任务要求，本轮只生成并检查迁移，未执行 `alembic upgrade`。

### 3.5 `frontend/src/pages/reports/ReportDetail.tsx`

- 待推送/失败任务显示“发送”“取消”；取消不弹二次确认。
- 已推送/已取消任务显示“删除”；推送中任务不显示操作。
- 删除使用 `Modal.confirm`，明确提示删除不可恢复且不会撤回已发送飞书消息。
- 已取消状态使用灰色 Tag。
- 发送与取消互相禁用，防止同一任务在请求期间重复操作。
- 发送、取消、删除成功或后端拒绝后均刷新任务列表；成功操作显示明确反馈。

### 3.6 `frontend/src/types/index.ts`

- `ReportPushStatus` 增加“已取消”，与后端枚举保持一致。
