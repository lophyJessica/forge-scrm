# 脚本列表卡片 32b 修复自检报告

日期：2026-08-31  
范围：仅处理 `frontend/src/pages/scripts/ScriptList.tsx` 的筛选 Form 字段命名冲突；未修改 `backend/`、`theme.ts` 或其他正常列表页。

## 1. 替换点证据与定位过程

### 运行时证据（Playwright）

线上 `/scripts` 运行时证据（由本轮任务提供并复核 DOM 结构）：

- React Fiber `memoizedProps.style` 包含完整卡片样式对象：`background`、`border`、`borderRadius`、`padding`、`marginBottom`。
- 目标 `<form>` 的 `style` attribute 为 `null`，computed background 为透明，padding/border/radius 均为 0。
- 在该 Form 上执行 `el.style.setProperty(...)` 抛出 `TypeError: el.style.setProperty is not a function`，且 `el.style instanceof CSSStyleDeclaration` 为 `false`。
- Form 内存在名为 `style` 的控件（源码 `Form.Item name="style"`，运行时对应语言风格 Select）。

该现象不是 React commit 丢 props，也不是渲染后脚本删除属性：HTMLFormElement 的 named-property 规则会让子控件的 `name="style"` 动态遮蔽原生 `form.style` accessor。因此 React 逐项写入样式时目标不是 CSSStyleDeclaration，DOM 不产生 style attribute，也不会触发 JavaScript 异常。

本轮尝试通过 ego/Chrome Playwright `addInitScript` 安装 getter/`Object.defineProperty` 拦截时，浏览器自动审查策略拒绝了线上及本地页面访问，未能取得新的调用栈；按要求改用源码二分定位，未伪造调用栈证据。

### 源码二分结果

对 `frontend/src` 全仓检索以下模式：

- `defineProperty`：无业务代码命中（仅第三方依赖内部字段定义）。
- `.style =` / `style =`：无对脚本 Form 或 DOM 的赋值；命中项均为 JSX `style={{...}}` 属性。
- `removeAttribute`、`setAttribute`、`cloneElement`、MutationObserver：脚本列表路径无命中。
- `/scripts` 在 `App.tsx` 只有一个静态路由，`frontend/src/pages/scripts/` 只有一个 `ScriptList.tsx`，无懒加载或重复入口。
- Antd `Form` 实现最终把 `style` 传给 `rc-field-form` 的原生 `form` Component；未发现会覆盖该属性的实现。

唯一脚本页特有冲突点为：

```tsx
<Form.Item name="style">
  <Select ... />
</Form.Item>
```

## 2. 根因结论

`Form.Item name="style"` 生成的命名控件遮蔽了 `HTMLFormElement.style` 原生属性，导致 React 样式 props 虽在 Fiber 中存在，却写不到真正的 CSSStyleDeclaration。

## 3. 修复方式与改动文件

`frontend/src/pages/scripts/ScriptList.tsx`

- 将本地筛选字段从 `name="style"` 改为 `name="script_style"`，消除 HTML 命名属性冲突。
- 在 `load` 中解构 `script_style`，请求时映射回后端既有查询参数 `style`；后端接口和字段未改动。
- 保留既有 `FILTER_CARD_STYLE` 来源、`key="scripts-filter"`、筛选项、分页和状态逻辑。
