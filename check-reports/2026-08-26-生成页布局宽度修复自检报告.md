# 生成页布局宽度修复自检报告

## 任务 / 项目

- 项目：Forge 新媒体运营系统。
- 任务：统一“批量生成选题”和“基于选题生成脚本”两页的卡片与表单宽度。
- 工作区：`/Users/liulongfei/个人文件/forge-scrm`。
- 本次未修改后端、`context/`、路由业务逻辑或表单字段；未 commit、未 push、未部署。

## 根因

- `App.tsx` 中 `/topics/generate` 和 `/scripts/generate` 都直接挂在同一个 `MainLayout` 路由出口下，没有额外容器分支。
- `MainLayout.tsx` 的 `<Content style={{ margin: 16 }}>` 对两个页面一致，`<Outlet />` 也没有页面差异化样式。
- 两个页面 JSX 外层均为 `Space width: 100%` → `Card` → `Form`，本地源码的表单约束也一致。
- 线上 Chrome 实测同一窗口宽度 1920px：选题页 `<form>` 计算宽度为 720px；脚本页 `<form>` 计算宽度为 1603px，且 computed `max-width` 为 `none`。脚本页线上 bundle 未呈现当前源码中的宽度约束，属于线上资源/样式未与当前源码一致，同时原实现依赖隐式 block width。

## 改动文件

- `frontend/src/pages/topics/TopicGenerate.tsx`
  - 卡片增加 `width: 100%`。
  - 表单改为 `width: 100%; max-width: 720px`。
- `frontend/src/pages/scripts/ScriptGenerate.tsx`
  - 卡片增加 `width: 100%`。
  - 表单改为 `width: 100%; max-width: 720px`。

其余字段、生成逻辑、模板库/自定义交互和 API 调用未改动。

## 验证过程

### 源码检查

- 对比 `App.tsx`：两条路由均位于同一 `MainLayout` 下，无不同容器处理。
- 对比 `MainLayout.tsx`：两页共用同一 `Content` 和 `Outlet`。
- 对比两个页面从 `return` 到主表单 `</Card>` 的 JSX：外层结构一致，差异不来自栅格或特殊字段宽度。
- 修复后两页都显式具备 `Card width: 100%` 和 `Form width: 100%; max-width: 720px`。

- 该结果确认了真实差异在脚本页线上渲染结果，不是路由布局分支。
