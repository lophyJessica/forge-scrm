# 姐夫新媒体运营系统：需求调研问题清单

> 填写人：姐夫、用户本人、后续执行调研的 Agent
> 目的：补齐业务事实、产品决策和平台事实，为后续范围确认提供依据。
> 题目数量：30 题，不是最终需求或 PRD。

## 填写说明

- 每题只填写当前知道的内容；“不清楚”“待确认”都是有效答案。
- 标记为“姐夫回答”的问题用于确认真实业务，不要求姐夫查询技术资料。
- 标记为“用户拍板”的问题是产品范围选择，不由 Agent 擅自决定。
- 标记为“Agent 调研”的问题将在后续获得授权后依据官方资料或系统状态核验。
- 回答收回后，应整理为已确认事实、待确认事实、产品决定和后续动作，不能直接把原始回答当作完整 PRD。

## 三、后续由 Agent 调研的平台事实

除第 18 题的账号数据接口外，下列内容不要求姐夫或用户自行查询。本轮只登记研究问题，不进行联网调研：

- Make、n8n、Activepieces、Windmill、Node-RED、Pipedream 和自建后端任务调度/队列分别是云端、自托管还是两者兼有；
- 各候选是否适合 LisaHost VPS，以及 4C + 4G + 80G 下的资源压力；
- Webhook、HTTP API、定时任务和代码/脚本节点能力；
- DeepSeek、飞书和自建后端 API 的接入方式；
- 重试、错误处理、执行日志、凭据管理、权限与协作；
- 备份恢复、成本、平台锁定风险和非技术用户维护难度；
- 目标内容平台对自己账号数据开放的官方接口、授权条件、导出能力和限制。

以上事实应在业务范围和评价权重明确后，由 Agent 依据官方文档、官方定价、官方部署要求或真实系统检查填写，并区分已确认事实、条件限制和建议。
