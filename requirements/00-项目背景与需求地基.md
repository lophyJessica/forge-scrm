## 2. 项目背景

项目目标是正式搭建“Forge 新媒体运营系统”，支持资料沉淀、内容生产和运营数据分析。

当前已存在一个 Make + DeepSeek + 飞书的内容生产 MVP，可作为业务现状参考；正式系统从需求地基开始重新梳理，不把现有 MVP 直接当成最终系统设计，也不把 Make 默认设为最终自动化平台。

当前业务闭环在阶段总结中被描述为：

```text
选题生成 → 脚本生成 → 人工录制/后期 → 发布 → 数据回收 → 周报与市场分析
```

其中已经跑通的是选题和脚本生成链路；资料库、完整内容管理、数据回收、周报和市场分析仍需调研或建设。

## 4. 当前 Make + 飞书 + DeepSeek MVP 现状

### 4.1 选题生成

已验证链路：

```text
Webhook
→ DeepSeek
→ Parse JSON
→ Create JSON
→ 飞书 API
→ 飞书《每周选题库》
```

已验证能力：

- Webhook 能够触发 DeepSeek；
- DeepSeek 能够生成 15 条不同选题；
- 结构化 JSON 能够被解析；
- 多条选题能够逐条写入飞书《每周选题库》。

《每周选题库》当前字段：

- 选题类型；
- 视频标题；
- 核心角度；
- 流量潜力；
- 状态。

### 4.2 脚本生成

已验证链路：

```text
网页表单
→ Webhook
→ DeepSeek
→ Create JSON
→ 飞书 API
→ 飞书《脚本库》
```

网页表单当前输入：

- `type`：选题类型；
- `topic`：核心主题；
- `info`：关键信息；
- `action`：目标行动。

已验证能力：

- 4 个字段可以动态传入 Webhook；
- DeepSeek 可以根据输入生成口播脚本；
- Create JSON 可以处理多行文本；
- 脚本可以写入飞书《脚本库》。

《脚本库》当前字段：

- 选题类型；
- 脚本全文。

### 4.3 当前网页入口和平台职责

现有网页入口：`https://pmlophy.com/make-form/`

当前实际职责：

- Make：Webhook、流程编排、调用 DeepSeek 和飞书 API；
- DeepSeek：生成选题和脚本；
- 飞书：保存结果并支持人工查看；
- 网页表单：为操盘手提供简单触发入口。

## 5. 当前 MVP 的边界和问题

### 5.1 已确认边界

- 当前只验证了选题和脚本的基础生成、处理与保存；
- 飞书当前保存结果，但不是已经确定的长期核心业务数据库；
- DeepSeek 当前负责文本生成，不管理业务记录、状态、权限或流程；
- Make 当前负责编排，但其长期职责尚未确定；
- 每周数据报告和市场分析报告尚未搭建；
- 当前网页表单不是完整运营管理后台。

### 5.2 已有资料记录的问题

- 飞书多维表格依赖字段配置；
- 字段、视图、权限和 Make 场景之间容易互相牵连；
- 业务状态和规则难以集中维护；
- 随着账号、平台、审核、发布记录和复盘数据增加，长期维护成本可能继续上升；
- Make 不一定是最终自动化平台，需要与其他候选及自建调度方案比较。

这些问题说明需要重新建立业务边界和选型标准，但不能直接推出某个最终技术方案。

## 6. 三大业务板块初步定义

三大板块名称统一为：

1. 资料库；
2. 选题库和脚本库；
3. 数据分析。

### 6.1 资料库

初步目标：沉淀可以被选题、脚本和数据分析调用的资料。

四类输入或处理方式必须分开：

| 方式 | 初步含义 | 当前状态 |
|---|---|---|
| 手动添加 | 由维护人直接录入，不默认配置自动能力 | 待确认资料范围和维护人 |
| 自动采集 | 对明确允许且具备稳定来源的资料配置采集 | 待确认来源、许可、频率和可行性 |
| CSV/TXT 导入 | 对只能导出或批量整理的数据进行文件导入 | 待确认格式、提供人和校验规则 |
| AI 分析 | 对需要加工的原始资料配置分析提示词，生成分析结果 | 待确认任务、提示词和结果结构 |

“AI 分析结果回写资料库”是初步设想，是否回写、回写到原资料还是新资料、是否需要审核均待确认。

### 6.2 选题库和脚本库

初步目标：通过可配置提示词，调用指定范围的资料库内容，生成并保存选题和脚本。

待确认能力：

- 提示词由谁配置、如何生效和版本化；
- 每次生成选择哪些资料范围；
- 选题如何引用资料；
- 脚本是否必须从选题继续生成；
- 选题与脚本如何关联；
- 生成结果是否人工修改、审核和保留多版本；
- 如何记录本次生成使用了哪些资料。

现有 Make MVP 只证明基础生成和飞书写入，不代表上述管理规则已经实现。

### 6.3 数据分析

初步目标：接收原始运营数据，按每类分析任务的提示词生成指定字段的结构化分析结果。

数据进入方式按可用条件选择：

- 官方或合法稳定接口可用时，评估自动采集；
- 无可用接口时，允许手动填写；
- 平台只能导出文件时，评估 CSV/TXT 导入；
- 每类分析任务可以有独立提示词和输出字段。

初步要求：不能只保存一段 AI 长文本；需要评估保存原始数据、提示词版本、分析时间和结构化输出。具体字段、任务和保存规则均待确认。

## 7. 板块之间的初步调用关系

以下是待确认的业务关系，不是技术架构：

```text
手动添加 / 自动采集 / CSV/TXT 导入
                    ↓
                  资料库
             ↙       ↓       ↘
         选题生成   脚本生成   数据分析
             ↓       ↓          ↓
          选题库   脚本库   结构化分析结果
             └── 待确认关联 ──┘
                         ↓
             AI 分析结果是否回写资料库
                         ↓
                       待确认
```

需要避免的混淆：

- “自动采集”解决资料或数据如何进入系统；
- “手动添加”解决人工维护；
- “CSV/TXT 导入”解决批量文件输入；
- “AI 分析”解决已有内容如何加工；
- “调用资料库”解决生成或分析时使用哪些已有资料。

## 8. 已确认事实

### 8.1 当前状态

- 当前项目从零建立需求地基，没有既定项目框架可沿用；
- LisaHost VPS 升级工单已提交，目标预计为 4C + 4G + 80G，升级尚未完成；

### 8.2 已跑通的 MVP 能力

- Make 场景能够通过 Webhook 触发 DeepSeek；
- 选题链路能够生成并解析 15 条选题，写入飞书《每周选题库》；
- 脚本链路能够接收表单 4 个动态字段，生成脚本并写入飞书《脚本库》；
- 飞书当前用于保存结果和人工查看；
- 网页表单当前为操盘手提供触发入口；
- Make、DeepSeek、飞书和网页表单的当前职责已经明确，但不构成未来职责结论。

### 8.3 已明确的方向性边界

- 正式系统暂按资料库、选题库和脚本库、数据分析三个板块调研；
- 不同资料可以分别采用手动添加、自动采集、CSV/TXT 导入或 AI 分析，不默认所有资料都自动化；
- 自动化平台仍需比较，Make 不是默认最终方案。
