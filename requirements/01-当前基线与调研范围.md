## 1. 项目背景

项目面向操盘手的新媒体运营工作，当前业务场景为“视频号商业 IP（中小微企业获客）”。现阶段已优先验证内容生产链路：

```text
VPS 网页表单 → Make Webhook/流程编排 → DeepSeek 文本生成 → 飞书多维表格保存
```

长期目标是建设“新媒体运营系统”，暂定包含前端管理后台、后端 API、MySQL、Nginx、对象存储、DeepSeek 和待选型的自动化能力。未来计划部署在 LisaHost VPS，但 VPS 升级仍在申请中，目标配置预计为 4C + 4G + 80G；当前不能假设升级已经完成，也不能据此开展安装或部署。

当前 Make、飞书和 DeepSeek 的组合是已经跑通的 MVP 链路，不构成长期架构结论。自动化平台仍需后续比较，不得默认继续使用 Make。

## 2. 当前已验证的 Make 能力

### 场景 1：选题生成

已记录为真实跑通的链路：

```text
Webhook
→ DeepSeek 生成 15 条选题 JSON 数组
→ Parse JSON
→ Create JSON
→ HTTP 获取飞书 tenant_access_token
→ HTTP 逐条写入飞书《每周选题库》
```

已验证结果：

- Webhook 可以被网页按钮触发；
- DeepSeek 返回的 15 条选题可以被解析和拆分；
- 15 条内容不同的选题可以逐条写入飞书；
- 当前部分选题输入仍偏固定，尚未证明所有选题条件都能动态配置。

### 场景 2：脚本生成

已记录为真实跑通的链路：

```text
网页表单
→ Webhook 接收 type、topic、info、action
→ DeepSeek 生成口播脚本
→ Create JSON 处理多行文本
→ HTTP 获取飞书 tenant_access_token
→ HTTP 写入飞书《脚本库》
```

已验证结果：

- 4 个字段可以从表单动态传入 Webhook；
- Make 可以将字段映射到 DeepSeek 的 User Prompt；
- DeepSeek 可以根据不同输入生成对应脚本；
- 多行脚本可以经 Create JSON 正确写入飞书，没有破坏请求 Body；
- 早期 Telegram 通道只是测试手段，当前正式保存位置是飞书。

### 当前边界

- Make 当前承担触发、编排和 API 调用，不是长期业务数据库；
- 每周数据报告和市场分析报告尚未搭建；
- 提示词配置表被描述为后续维护方向，现有资料不足以证明场景已在每次运行时读取该配置表；
- 新增业务字段仍需要同步修改表单、Webhook 契约、Make 映射和写入规则，尚未具备任意字段自动适配能力。

## 6. 三大业务板块的目标描述

以下内容是当前需求目标，不代表已经实现或已经完成业务验收。

### 6.1 资料库

目标职责：沉淀可被选题、脚本和数据分析调用的资料。

计划入口包括：

- 手动添加：不需要额外采集功能；
- 自动采集：针对需要采集的资料配置采集能力；
- CSV/TXT 导入；
- 资料分析：针对需要分析的资料配置提示词；
- 向选题生成、脚本生成和数据分析提供可引用内容。

初步边界：资料的来源、类型、采集方式、更新频率、使用权限和引用方式尚未确认；“自动采集”不是所有资料的默认能力。

### 6.2 选题库和脚本库

目标职责：通过配置提示词并调用相关资料库内容，生成、保存和管理文本结果。

计划能力包括：

- 配置生成提示词；
- 调用资料库内容；
- 生成并保存选题和脚本；
- 人工修改、审核和使用；
- 保存提示词版本；
- 保存生成结果与资料引用关系。

初步边界：当前已跑通的两条 Make 链路只证明基础生成和飞书写入，不等于上述版本管理、引用追踪、审核状态和完整管理流程已经实现。

### 6.3 数据分析

目标职责：接收账号或市场原始数据，通过可配置提示词生成指定字段的结构化分析结果。

计划入口和处理方式包括：

- 能稳定采集自己账号数据时自动采集；
- 不能采集时手动填写；
- 支持 CSV/TXT 导入；
- 配置分析提示词；
- 配置输出字段；
- 保存原始数据、提示词版本、分析时间和结构化结果。

初步边界：账号平台、数据来源、可采集性、指标口径、分析周期、输出字段及质量验收均未确认。阶段总结中的“每周数据报告”和“市场分析报告”都尚未搭建。
