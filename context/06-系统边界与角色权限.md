## 1. 系统边界

### 1.1 自建运营系统（一期核心）

- 资料库管理（分类/标签/审核/有效期/可信度/搜索/调用）
- 提示词配置中心（选题/脚本/分析模板 + 版本）
- 选题库（批量生成/去重/历史/人工筛选）
- 脚本库（多版本生成/挑选/状态）
- 手动录入 + CSV/TXT 导入：内容资料进入资料库，账号指标进入数据分析原始数据
- 自动采集数据源/任务/API 扩展结构预留，不实际接入视频号或运行采集任务（D5）
- 基础数据分析（录入/导入→通用分析框架→状态流转→人工审核→回写/反哺），深度指标二期（D6）
- 数据存储（MySQL 业务数据 + 对象存储媒体/原始文件）

### 1.2 外部能力（通过 API 调用）

- DeepSeek：文本生成（选题/脚本）与数据分析
- 自动化平台（Make/n8n 等，待选型）：外部编排/通知，只调后端 API，不直接写库；一期不配置定时采集（D2）
- 飞书：过渡期脚本库/选题库查看、通知协作（不承担核心数据源）
- 视频号/小红书：自动采集二期评估；一期无视频号账号，使用手动录入/CSV（D5）

### 1.3 明确不做

- 平台发布/内容上传（运营人员人工完成）
- 电商交易/订单
- 多租户 SaaS
- 一期不做完整 RBAC 自定义角色体系和操作审计；一期仍实现管理员/成员两级基础账号与权限隔离

## 3. 数据与存储边界

- MySQL：结构化业务数据（资料/选题/脚本/分析/提示词/状态/引用/任务元数据）
- 对象存储：CSV/TXT 原文件、媒体、原始 AI 响应、大文件
- DeepSeek：只做生成/分析，不保存业务状态
- 自动化平台：只编排，不直接写 MySQL（通过后端 API + 幂等）
- 采集归属：一期通过手动录入/CSV 导入；自动采集相关表和接口只作架构预留。内容资料进入资料库，账号指标进入数据分析原始数据。

## 4. 过渡期与长期目标

- 过渡期：Make 现有选题/脚本链路保留运行；飞书继续作为临时查看端；
- 中期：自动化平台改调后端 API；有视频号账号后再评估官方 API 采集试点；启用初期仅人工触发，不做定时任务；
- 长期：自建系统成为唯一业务事实源，自动化平台退为可替换执行层。
