## 1. 主业务闭环

```mermaid
flowchart LR
    subgraph ENTRY["数据入口"]

    MATERIAL["资料库<br/>有效期 / 可信度 / 来源"]
    TOPIC["选题库<br/>按方向生成 / 完全重复去重"]

    ANALYSIS["数据分析<br/>执行 / 确认 / 双向回写"]
    RESEARCH["研究助手<br/>二期范围研究与来源追溯"]
    REPORT["数据报告<br/>模板 / 生成 / 来源快照"]
    FEISHU["飞书卡片推送"]

    MANUAL --> MATERIAL
    IMPORT --> MATERIAL
    COLLECT --> MATERIAL
    MATERIAL --> TOPIC --> SCRIPT --> PUBLISH
    PUBLISH -. "平台运营后回收数据" .-> DATA
    MANUAL --> DATA
    IMPORT --> DATA
    COLLECT --> DATA
    DATA --> ANALYSIS
    MATERIAL --> RESEARCH
    COLLECT --> RESEARCH
    ANALYSIS --> REPORT
    RESEARCH --> REPORT
    REPORT --> FEISHU
    ANALYSIS -->|"回写 AI 资料"| MATERIAL
    ANALYSIS -->|"反哺选题"| TOPIC

    RESEARCH -->|"生成选题"| TOPIC
    RESEARCH -->|"基于选题生成脚本"| SCRIPT
```

主链以一期的资料、选题、脚本和基础分析为骨架。二期自动采集增加资料与运营数据入口；研究助手并行消费资料、采集结果和外部检索，数据报告汇总分析与研究产物，飞书负责系统外输出。

## 2. 各模块核心业务流程

### 2.1 资料库

```mermaid
flowchart TD
    START{"资料进入方式"}
    MANUAL["/materials/new<br/>填写标题、正文、分类、来源、可信度、有效期、标签"]
    IMPORT["/materials/import<br/>下载导入模板 → 选择文件并导入"]
    CHECK["文件级与逐行校验<br/>成功行入库，失败行展示行号与原因"]
    DRAFT["草稿<br/>可点“保存”进入可用状态"]
    ACTIVE["已生效<br/>可搜索和进入下游资料选择器"]
    META["/material-classes + /tags<br/>分类管理 / 自由标签"]
    COMBO["/admin/prompt-templates<br/>固定资料组合随模板复用"]
    DOWNSTREAM["选题 / 脚本 / 分析 / 研究引用"]
    DISABLED["已停用"]
    EXPIRED["已过期"]
    DISCARDED["已废弃"]

    START -->|"手动录入"| MANUAL
    START -->|"CSV / TXT"| IMPORT --> CHECK
    MANUAL -->|"存为草稿"| DRAFT
    MANUAL -->|"保存"| ACTIVE
    CHECK --> ACTIVE
    META -. "分类与标签" .-> ACTIVE
    ACTIVE -->|"选择为固定组合"| COMBO --> DOWNSTREAM
    ACTIVE --> DOWNSTREAM
    ACTIVE -->|"停用"| DISABLED
    DISABLED -->|"启用"| ACTIVE
    ACTIVE -->|"有效期到期"| EXPIRED
    EXPIRED -->|"确认废弃"| DISCARDED
```

**关键状态流转**：`草稿 → 已生效 → 已停用 → 已生效`；`已生效 → 已过期 → 已废弃`。只有已生效资料进入选题、脚本、分析和研究的资料选择器；原始资料与 AI 回写资料必须保留来源和产物标记。

| 涉及页面 | 关键动作按钮（源码原文） | 流转结果 |
|:--|:--|:--|
| `/materials` | `批量导入`、`新建资料`、`查询`、`编辑`、`停用`、`启用`、`确认废弃` | 查询与维护资料生命周期 |
| `/materials/new`、`/materials/:id` | `存为草稿`、`保存`、`取消` | 创建草稿或保存为当前可用口径 |
| `/materials/import` | `下载导入模板`、`选择文件并导入` | 成功行入库，失败行保留行号和原因 |
| `/material-classes`、`/tags` | `新建分类`、`编辑`、`保存`、`新建标签` | 维护资料分类与标签 |
| `/admin/prompt-templates` | `新建模板`、`保存` | 在提示词模板中选择固定资料组合 |

### 2.2 选题库

```mermaid
flowchart TD
    ENTRY["/topics/generate<br/>选择业务方向 + 专业方向"]
    PARAM["选择已生效资料与提示词<br/>每方向固定 10 条"]
    GENERATE["点击“开始生成”<br/>调用 DeepSeek"]
    DEDUPE["历史全表 + 本批次<br/>标题完全重复去重"]
    RESULT["保存批次与 AI 原始响应<br/>展示返回 / 去重 / 入库数量"]
    PENDING["待筛选"]
    SELECTED["已选定"]
    DISCARDED["已废弃"]
    SCRIPT["/scripts/generate<br/>生成脚本"]
    GENERATED["已生成脚本"]
    USED["已使用"]

    ENTRY --> PARAM --> GENERATE --> DEDUPE --> RESULT --> PENDING
    PENDING -->|"选中"| SELECTED
    PENDING -->|"淘汰"| DISCARDED
    PENDING -->|"修改后选中"| SELECTED
    SELECTED -->|"生成脚本"| SCRIPT --> GENERATED --> USED
```

**关键状态流转**：`待筛选 → 已选定 / 已废弃`；`已选定 → 已生成脚本 → 已使用`。当前只做标题完全一致去重，保留批次历史；人工可修改选题，但不建立选题版本表。

| 涉及页面 | 关键动作按钮（源码原文） | 流转结果 |
|:--|:--|:--|
| `/topics` | `批量生成`、`导出 CSV`、`手动新增`、`详情`、`选中`、`淘汰` | 进入生成页、导出、创建或完成筛选 |
| `/topics/generate` | `+ 新增业务方向`、`+ 新增专业方向`、`开始生成`、`去列表筛选` | 生成 10 条候选并查看批次结果 |
| `/topics/batches` | `查看选题` | 按批次回看生成结果 |
| `/topics/:id` | `查看 AI 原始响应`、`修改`、`选中`、`淘汰`、`生成脚本` | 查看追溯、筛选或派生脚本 |
| `/topics/:id/edit`、`/topics/new` | `保存`、`取消` | 修改既有选题或手动新增 |

```mermaid
flowchart TD
    SOURCE{"创建方式"}
    TOPIC["/scripts/generate<br/>选择已选定选题"]

    SOURCE -->|"基于选题生成"| TOPIC --> VERSIONS --> DRAFT
    SOURCE -->|"独立创建"| STANDALONE --> DRAFT
```

**关键状态流转**：用户可见主路径为 `草稿 → 已通过 → 已使用`，草稿或已通过脚本可废弃。每次修改和回退都新增版本记录，不覆盖历史；“已使用”是人工标记，不代表已发布到内容平台。

| 涉及页面 | 关键动作按钮（源码原文） | 流转结果 |
|:--|:--|:--|
| `/scripts` | `独立创建`、`基于选题生成`、`详情`、`版本`、`标记已使用`、`废弃` | 进入创建、生成、版本或生命周期动作 |

| `/scripts/:id` | `版本历史`、`修改`、`标记已使用`、`废弃` | 维护当前脚本与业务状态 |
| `/scripts/:id/versions` | `查看差异`、`查看快照`、`回退`、`返回脚本` | 对比历史并以新版本方式回退 |

### 2.4 自动采集

```mermaid
sequenceDiagram
    actor U as 操盘手
    participant A as 对标账号页
    participant T as 自动采集任务页
    participant API as SCRM API
    participant S as 外部公开来源
    participant DB as MySQL

    U->>A: 点击“新建账号”并“保存”
    A->>API: 平台、账号标识、主页 URL
    API->>DB: 保存启用账号
    U->>T: 点击“新建采集任务”
    T->>API: 账号 + 时间窗 + 可选公开 URL
    API->>DB: 检查账号、范围、时间窗完全相同任务
    alt 发现重复任务
        API-->>T: 返回旧任务编号、状态、结果数
        T-->>U: “查看旧任务” / “关闭”
    else 创建成功
        API->>DB: 新建任务（待执行）
        API-->>T: 任务已创建
        U->>T: 点击“执行”
        T->>API: 人工触发采集
        API->>DB: 状态改为执行中，拆分账号记录
        loop 每个账号或来源
            API->>S: 请求公开内容
            S-->>API: 原始响应或错误
            API->>DB: 保存记录、原始事实、结构化结果或错误
        end
        API->>DB: 汇总为已完成 / 部分成功 / 失败
        API-->>T: 返回任务进度和结果
    end
    opt 失败记录可重试
        U->>T: 点击记录级“重试”
        T->>API: 只重试失败记录
        API->>DB: 保留旧尝试，不重复写成功结果
    end
    U->>T: 点击“沉淀为资料”或“作为分析输入”
    T->>API: 创建资料草稿或跳转分析任务预选结果
```

**关键状态流转**：任务 `待执行 → 执行中 → 已完成 / 部分成功 / 失败`，失败任务可“重试”；记录 `待执行 → 执行中 → 已完成 / 失败`，可重试记录只处理失败项。采集结果是原始事实，默认不是 AI 产物。

| 涉及页面 | 关键动作按钮（源码原文） | 流转结果 |
|:--|:--|:--|
| `/collection/benchmark-accounts` | `新建账号`、`编辑`、`保存` | 维护可选对标账号 |
| `/collection/tasks` | `新建采集任务`、`创建`、`查看旧任务`、`执行`、`重试` | 创建、识别重复、执行任务或任务级重试 |
| `/collection/tasks` 展开行 | `详情`、`沉淀为资料`、`作为分析输入`、记录级 `重试` | 查看结果、进入资料库或分析链 |
| `/collection/tasks` 资料弹窗 | `保存资料`、`取消` | 补齐分类、可信度和有效期后生成资料草稿 |

### 2.5 数据分析

```mermaid
sequenceDiagram
    actor U as 用户
    participant D as 数据准备页
    participant T as 分析任务页
    participant API as SCRM API
    participant AI as DeepSeek API
    participant DB as MySQL

    U->>D: “手动录入”或“上传 CSV”
    D->>API: 原始内容、结构化数据、时间窗
    API->>DB: 保存原始事实与来源
    U->>T: 点击“新建分析任务”
    T->>API: 原始数据 / 采集结果 + 已生效资料 + 可选模板
    API->>DB: 创建任务（待执行）并固化输入快照
    U->>T: 点击“执行”
    T->>API: 执行任务
    API->>DB: 状态改为执行中
    API->>AI: 发送提示词和上下文
    alt 输出通过结构校验
        AI-->>API: 结构化结果
        API->>DB: 已完成并按用户可见口径进入已确认
        API-->>T: 展示效果、结论、建议、依据
        U->>T: 点击“回写资料库”并“确认回写”
        T->>API: 提交资料字段
        API->>DB: 创建带 AI 产物标记的资料
        U->>T: 点击“反哺选题库”并“确认反哺”
        T->>API: 提交候选选题
        API->>DB: 创建待筛选选题
    else 调用或校验失败
        API->>DB: 状态改为失败并保留错误、响应和重试次数
        API-->>T: 显示错误
        U->>T: 点击“重新执行”
    end
```

**关键状态流转**：`待执行 → 执行中 → 已完成 → 已确认`；执行失败进入 `失败`，点击“重新执行”后回到执行中。资料回写与选题反哺是两个独立动作，分别留痕，AI 资料不得覆盖原始事实。

| 涉及页面 | 关键动作按钮（源码原文） | 流转结果 |
|:--|:--|:--|
| `/analysis/data-sources` | `新增数据源`、`编辑`、`保存` | 维护数据来源口径 |
| `/analysis/raw-data` | `手动录入`、`下载导入模板`、`上传 CSV`、`保存` | 保存手动或导入的原始数据 |
| `/analysis/tasks` | `新建分析任务`、`创建`、`执行`、`重新执行`、`详情` | 创建、执行或重试分析任务 |
| `/analysis/tasks/:id` | `AI 原始响应`、`执行`、`重新执行`、`回写资料库`、`反哺选题库` | 查看追溯并发起下游动作 |
| `/analysis/tasks/:id` 回写弹窗 | `添加一条`、`确认回写`、`确认反哺` | 编辑候选并分别写入资料库或选题库 |

### 2.6 研究助手

```mermaid
flowchart TD
    CREATE["/research/tasks<br/>新建研究任务"]
    SCOPE["选择主题、目标、时间窗<br/>资料库 / 自动采集结果 / 外部检索"]
    PENDING["待执行"]
    SEARCH["检索中<br/>阶段进度 + checkpoint + 来源数"]
    ORGANIZE["整理中<br/>复用已保存来源形成章节和结论"]
    COMPLETE["已完成<br/>生成研究报告与引用关系"]
    FAILED["失败<br/>保留最近错误、来源和 checkpoint"]
    REPORT["/research/reports/:id<br/>摘要 / 正文 / 章节 / 结论 / 引用"]
    MATERIAL["沉淀为资料<br/>AI 产物标记"]
    TOPIC["生成选题<br/>完全重复去重"]
    SCRIPT["生成脚本<br/>必须选择已选定选题，2-3 版"]

    CREATE --> SCOPE -->|"创建"| PENDING
    PENDING -->|"执行 / 开始执行"| SEARCH --> ORGANIZE --> COMPLETE --> REPORT
    SEARCH -->|"中断或来源失败"| FAILED
    ORGANIZE -->|"整理或结构校验失败"| FAILED
    FAILED -->|"重试"| SEARCH
    REPORT -->|"沉淀为资料 / 确认沉淀"| MATERIAL
    REPORT -->|"生成选题 / 确认生成"| TOPIC
    REPORT -->|"生成脚本 / 确认生成"| SCRIPT
```

**关键状态流转**：`待执行 → 检索中 → 整理中 → 已完成`；任一执行阶段失败进入 `失败`，重试时复用已保存来源和 checkpoint。报告与结论是 AI 产物，引用的原始资料、采集结果和外部 URL 保持独立。

| 涉及页面 | 关键动作按钮（源码原文） | 流转结果 |
|:--|:--|:--|
| `/research/tasks` | `新建研究任务`、`创建`、`执行`、`重试`、`详情`、`查看报告` | 创建、执行、恢复或查看研究任务 |
| `/research/tasks/:id` | `开始执行`、`重试`、`返回列表` | 查看阶段、进度、来源数、checkpoint 和错误 |
| `/research/reports/:id` | `沉淀为资料`、`生成选题`、`生成脚本` | 从报告发起三个独立下游动作 |
| `/research/reports/:id` 确认弹窗 | `确认沉淀`、`确认生成`、`取消` | 补齐目标字段后创建资料、选题或脚本 |

### 2.7 数据报告

```mermaid
sequenceDiagram
    actor U as 用户
    participant L as 数据报告页
    participant API as SCRM API
    participant R as 报告生成器
    participant DB as MySQL
    participant F as 飞书

    U->>L: 点击“新建报告”
    L-->>U: 选择类型、周期、模板和来源范围
    U->>L: 点击“创建并生成”
    L-->>U: “确认报告口径” → “确认并生成”
    L->>API: 创建报告并触发生成
    API->>DB: 待生成 → 生成中，保存来源配置
    API->>R: 聚合来源快照并按模板生成
    alt 生成成功
        R-->>API: 摘要、正文、章节、结论
        API->>DB: 状态改为已完成，保存来源快照与 AI 标记
        API-->>L: 展示报告详情
        U->>L: 点击“创建推送”并“创建”
        L->>API: 创建飞书推送任务（待推送）
        U->>L: 点击“发送”
        API->>DB: 推送中，创建发送记录
        API->>F: 发送飞书卡片
        alt 飞书确认成功
            F-->>API: 成功
            API->>DB: 已推送，记录发送时间
        else 飞书失败
            F-->>API: 限流、超时或授权错误
            API->>DB: 失败，记录错误与尝试序号
            U->>L: 再次点击“发送”重试
        end
    else 生成失败
        R-->>API: 错误或结构缺失
        API->>DB: 状态改为失败，保留来源配置和错误
        U->>L: 点击“重试”
    end
```

**关键状态流转**：报告 `待生成 → 生成中 → 已完成 / 失败`，失败可重试；飞书推送 `待推送 → 推送中 → 已推送 / 失败`，未发送或失败任务可取消，失败任务可再次发送。推送失败不回滚报告状态。

| 涉及页面 | 关键动作按钮（源码原文） | 流转结果 |
|:--|:--|:--|
| `/reports` | `新建报告`、`创建并生成`、`确认并生成`、`生成`、`重试`、`查看` | 配置口径、生成、重试或查看报告 |
| `/report-templates` | `新建模板`、`编辑`、`设为默认`、`保存` | 维护两类报告的输出模板 |
| `/reports/:id` | `创建推送`、`推送任务`、`创建`、`发送`、`取消`、`删除` | 创建飞书任务并查看、执行或管理任务 |
| `/reports/:id` 推送任务抽屉 | `发送`、`取消`、`删除` | 展开每次发送记录、状态、错误和尝试序号 |

## 3. 权限边界

| 边界 | 管理员 | 成员 | 当前代码依据 |
|:--|:--|:--|:--|
| 登录与个人账号 | 账号密码登录；可在 `/profile` 查看账号并修改密码 | 同管理员 | `MainLayout` 无 token 跳转 `/login`；`Login.tsx`、`Profile.tsx` |
| 侧栏菜单 | 显示一期导航、内容管理、模板管理、AI 模块、权限管理 | 只显示首页及 `NAV_GROUPS`：资料库、选题库、脚本库、数据分析（含数据报告与报告模板） | `visibleGroups = isAdmin() ? ALL_NAV_GROUPS : NAV_GROUPS` |
| 管理员路由 | 可进入 `/admin/users`、`/admin/prompt-templates` | 路由守卫返回 403 | `App.tsx` 的 `RequireAdmin` |
| 一期业务动作 | 默认拥有全部功能权限 | 按 `functional_permissions` 显式授权，且受数据范围约束 | `useAuthStore.can()` 与后端 `require_permission()` |
| 二期采集与研究路由 | 菜单可见，可直接进入 | 菜单隐藏；`App.tsx` 未使用 `RequireAdmin` 包裹，直接路径的前端路由层不阻断 | 采集与研究的当前路由定义 |
| 报告与模板 | 报告入口可见；模板配置与推送动作按功能权限控制 | 数据分析组菜单可见；无相应权限时配置按钮隐藏或后端拒绝 | `/reports`、`/report-templates` 页面权限判断与后端依赖 |

菜单可见性不等于动作授权。成员即使能进入业务页面，也只能执行已显式授权且数据范围允许的动作；当前采集与研究的菜单隐藏和直接路由行为不完全等价，使用时应以页面、接口共同校验结果为准。

## 5. 产品设计边界

- **系统外人工运营**：视频号、小红书的内容发布、上传和平台内运营由人员完成；系统内“已使用”不等于平台发布成功。
- **预留能力**：定时采集、微信推送、语义去重、内容平台直接发布和经验证的官方平台专用适配均不作为当前已落地能力。
- **DeepSeek API**：负责选题、脚本、分析、研究整理和报告生成；失败必须保留错误与可追溯响应，不由模型补造缺失事实。
- **飞书**：当前报告卡片输出通道；授权、接收人和限流属于外部依赖，发送失败不影响报告本身。
- **MySQL**：保存结构化业务数据、状态、任务和引用；媒体、导入原文件与大文件按架构进入对象存储，本地环境可能仍使用文件系统。
- **外部检索与采集来源**：必须遵守来源授权、服务条款和访问限制；不可达或不合规时明确失败，不伪造成功或引用。
