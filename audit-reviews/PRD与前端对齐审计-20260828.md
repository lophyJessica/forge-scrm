> 审计日期：2026-08-28  
> 审计基线：`main` / `94ec38c`  
> 审计性质：只读审计；未修改业务代码、`context/` 或 `prd-docs/`  
> 权威顺序：`context/` > `prd-docs/主PRD.md`、模块主 PRD、字段清单、MVP 验收清单；`draft/`、`requirements/` 不作为判定依据

## 1. 审计方法与边界

本次从两侧建立清单后做双向比对：

1. 页面侧遍历 `frontend/src/pages/` 下 33 个页面文件，以及 `frontend/src/App.tsx`、`frontend/src/layouts/MainLayout.tsx` 的路由和菜单。
2. PRD 侧读取 `context/04-业务规则与状态机.md`、`context/05-术语与字段口径.md`、`context/06-系统边界与角色权限.md`，以及 `prd-docs/主PRD.md`、`prd-docs/mvp验收清单.md`、各模块主 PRD/字段清单和已确认迭代 PRD。
3. “待确认”“建议”“预留”不直接判为阻塞缺口；只有 PRD 明确列为 In Scope/验收项，或 context 已确认的规则，才进入缺口或偏差表。
4. 本次只审计前端可见功能及路由，不用前端现象反推后端算法是否正确。例如跨批次去重、状态落库幂等只能确认前端入口/反馈，不能代替后端审计。
5. `prd-docs/modules/审核流程变更说明.md` 明确写有“待回写 context”，其 R3/R6/R8 默认通过建议与现行 `context/04` 冲突时，仍以 context 为准。

## 5. 特别关注点结论

### 5.1 资料库

- 已有：列表筛选、分类/标签、CSV/TXT 导入、导入待审核、审核页、可信度/有效期展示、AI 产物标记。
- 主要问题：人工创建缺有效期且没有草稿/提交审核双动作（D1）；成员审核被错误拦截（D2）；固定组合只有选择没有 MVP 要求的引用预览（G1）。
- 结论：R1/R2 的前端闭环不完整，是当前最明确的 MVP 阻塞。

### 5.2 选题库

- 已有：方向/专业方向即建即用、资料选择、生成批次、筛选、修改、进入脚本、AI 原始响应入口。
- R14：前端有“完全重复跨批次去重”说明及 saved/deduped 反馈，但算法正确性需后端另审。
- 主要问题：数量可改为 1-10，与 context 的“每方向 10 条”不一致（D3）；保存的模板不能被再次选择（G3）。

### 5.3 脚本库

- 每选题 2-3 版、独立创建、后补选题、版本历史/对比/回退、管理员审核、人工标记已使用均有对应页面和操作。
- 本轮未发现 R5/R11/R15 的前端阻塞缺口；仍需后端测试确认版本落库和回退语义。

### 5.4 数据分析

- 状态、失败重试、人工审核、未确认前拦截回写、资料回写和选题反哺均已覆盖，符合 R6/R7 的 context 口径。
- 主要问题是删除类写操作缺正式规则（A2-A4），以及正式模板管理入口缺分析任务类型（D4）。

### 5.5 数据报告与推送

- 已有报告生成/重试、来源缺口展示、AI/审核状态展示、飞书配置脱敏、推送任务状态（含已取消）、发送/重试/取消/删除。
- 主要缺口：报告模板与来源配置、抽查/沉淀、推送 records 明细（G12-G15）。
- 文档滞后：报告删除功能和“已推送凭证不可删”均来自后续拍板，但正式 PRD 尚未同步（A1、D10）。

### 5.6 手机端适配

- 未发现手机端专用页面、路由、底部导航或移动业务流程。
- `index.css:16-17` 明确 `min-width: 1280px`，符合“一期桌面端、手机端专项二期”的范围；个别 antd `xs/sm` 响应式列仅用于防溢出，不构成手机端专项超前实现。

### 6.2 最优先修复 Top 5

1. **资料人工创建闭环（D1）**：恢复有效期、保存草稿、提交审核；直接影响 M01/M07 和 R1/R2。
2. **提示词模板可用性（D4 + G3）**：正式管理入口补分析类模板，生成页可选择已保存启用模板；影响内容生成和 M25。
3. **选题固定 10 条（D3）**：按现行 context 锁定每方向 10 条，或先完成规则回写再放开数量。
4. **二期 P0 研究/采集闭环（G5/G6/G10/G11）**：先补记录级重试、内部来源回点和研究结果下游动作。
5. **数据报告闭环（G12-G15）**：补模板/来源、抽查/沉淀和完整推送记录，同时回写报告删除与发送凭证规则。

## 7. 建议的对齐顺序

1. 先由产品确认“后续口头/指令拍板但未进正式 PRD”的两项：报告删除、已推送凭证不可删；确认后只补 PRD，不回退现有代码。
2. 先修 context/MVP 明确冲突：D1、D2、D3、D4、G1。
3. 再补二期 P0：自动采集和研究助手的失败恢复、来源追溯、下游使用链路。
4. 最后补二期 P1 报告模板、来源、抽查、沉淀和推送记录明细。
5. 对 A2-A4 的删除能力先补保留/关联保护规则，再决定保留入口；不要只靠前端二次确认。

## 8. 遗留风险

- 本报告只审计前端与正式文档，未运行端到端业务用例，无法确认后端去重、权限、状态并发、快照和关联删除保护是否真实生效。
- `审核流程变更说明.md` 与 context 的审核口径尚未统一；在 context 未回写前，任何“默认通过”都不能被视为替代 R1/R3/R6/R8 的正式 SSOT。
- `analysis/PromptTemplates.tsx` 是不可达遗留页面。本次按只读红线未删除；若后续清理文件，须另行取得用户确认。
- 报告删除和推送凭证删除规则存在“代码按后续拍板、PRD仍为旧口径”的历史差异，必须优先回写文档，否则后续 Agent 很可能再次按旧 PRD 回退。
