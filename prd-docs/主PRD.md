## 1. 产品概述

面向账号操盘手（姐夫）的新媒体运营系统，一期实现：

- 资料库：手动添加、分类标签、搜索调用、审核、有效期/可信度管理；
- 选题库：按方向批量生成（每方向10条）、跨批次去重、历史保留、人工筛选；
- 脚本库：基于选题生成 2-3 版脚本，人工挑选/修改，状态流转；
- 数据采集：自动采集 + 手动录入 + CSV/TXT 导入；
- 数据分析：提示词 + 资料上下文 → 结构化输出 → 人工审核 → 回写资料库/反哺选题。

## 3. 用户故事

1. 作为操盘手，我要手动添加一条商业研究结论，并选择分类、填写来源、有效期和可信度，以便后续生成选题时引用。
2. 作为操盘手，我要系统自动采集用户评论/私信和对标账号信息，以便沉淀用户洞察。
3. 作为操盘手，我要按方向批量生成10个选题，并且系统避免与其他批次重复，以便有足够候选可选。
4. 作为操盘手，我要人工筛选选题，标记可用/废弃，以便保证内容质量。
5. 作为操盘手，我要基于选定选题生成2-3个脚本版本，以便挑选最佳表达。
6. 作为操盘手，我要录入/导入视频号数据，运行分析任务，并请审核通过后回写资料库、生成新选题。

## 4. 核心流程

- 资料入库 → 审核 → 生效 → 被引用：见 context/02-2
- 选题生成 → 去重 → 筛选 → 可用 → 进脚本：见 context/02-3
- 脚本生成 → 2-3版 → 挑选 → 审核 → 使用：见 context/02-4
- 数据采集/录入 → 分析 → 审核 → 回写/反哺：见 context/02-5

## 5. 状态机

- 资料：草稿 → 待审核 → 已生效 → 已停用/已过期/已废弃
- 选题：待筛选 → 已选定(派生) → 已生成脚本 → 已使用(派生)/已废弃
- 脚本：草稿(派生) → 待审核 → 已通过 → 已使用(派生)/已废弃
- 分析任务：待执行 → 执行中 → 已完成 → 待审核 → 已确认/已废弃（失败可重试）

详见 context/04。

## 8. 验收标准（MVP）

### 8.1 必须验收

- [ ] 资料手动添加 → 分类 → 审核 → 生效 → 可被搜索；
- [ ] 按方向批量生成10条选题，跨批次去重有效；
- [ ] 选题人工筛选（可用/废弃）；
- [ ] 基于选题生成2-3版脚本；
- [ ] 脚本状态流转（待审核→已通过/已废弃）；
- [ ] 手动录入数据 → 创建分析任务 → 结构化输出 → 人工审核；
- [ ] 分析结果可回写资料库、生成新选题；
- [ ] 数据自动采集（至少一个来源试点）+ 手动/CSV 兜底；
- [ ] MySQL 数据持久化，重启不丢。

### 8.2 非功能

- 服务重启后自动恢复；
- 生成任务失败可重试，保留错误记录；
- AI 原始响应留档，可追溯；
- 敏感 key 不出现在日志；
- VPS 升级后 4C+4G 资源占用稳定（MySQL+API+Nginx+任务）。
