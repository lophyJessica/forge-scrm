# 自动采集_用例数据推演

> 文件定位：自动采集模块强制关卡——带字段值、状态快照和结果链路的用例推演
> 配套：自动采集主PRD、自动采集字段清单、自动采集_业务规则规格、自动采集_业务流程推演
> 通过条件：正常采集、部分失败、任务级失败重试、重复任务提示、资料库/分析链路使用五类用例均可闭环。

## 一、数据基线

### 1.1 对标账号样例

| id | platform | account_identifier | account_name | benchmark_flag | enabled |
|---:|---|---|---|---|---|
| 101 | 小红书 | xhs:acme_marketing | 增长研究所 | true | true |
| 102 | 视频号 | wx:brand_lab | 品牌实验室 | true | true |
| 103 | 小红书 | xhs:old_account | 已停用示例 | true | false |

### 1.2 任务配置样例

```json
{
  "task_no": "CT20260826-001",
  "trigger_type": "manual",
  "scope_type": "benchmark_account",
  "scope_config": {"benchmark_account_ids": [101, 102], "content": true, "metrics": true},
  "time_window_start": "2026-08-24T00:00:00+08:00",
  "time_window_end": "2026-08-25T23:59:59+08:00",
  "status": "待执行"
}
```

> `scope_config` JSON 结构、时间时区和任务编号均为示例/新增建议，待确认。

## 三、用例 AC-TC-01：正常采集全流程

### 场景

操盘手查看两个对标账号在 2026-08-24 至 2026-08-25 的更新内容和可用指标。

### 前置条件

管理员已登录；账号 101、102 启用；来源接口经过允许采集的实测；没有相同幂等条件的历史任务。接口字段仍待实测。

### 操作步骤

1. 确认 101、102 启用。
2. 创建任务，选择账号 `[101,102]`、范围 `benchmark_account` 和时间窗。
3. 确认创建，检查任务为 `待执行`。
4. 点击开始采集，检查任务变为 `执行中`。
5. 等待两条记录完成，打开结果详情。

### 预期结果

任务 `CT20260826-001` 创建成功但不自动开始；生成记录 `9001`、`9002`；两条记录成功，任务为 `已完成`；结果可通过记录和任务回溯账号、平台、来源 URL 和时间窗；原始结果 `is_ai_product=false`，不进入 AI 审核阻塞队列。

### 关键数据示例

```text
collection_task:
task_no=CT20260826-001 status=已完成 total_count=2 success_count=2 failure_count=0
time_window_start=2026-08-24 00:00:00 time_window_end=2026-08-25 23:59:59

collection_record 9001:
task_id=1 benchmark_account_id=101 status=成功 item_count=2 attempt_no=1
source_url=https://example.invalid/xhs/acme_marketing/post/123

collection_result 70001:
record_id=9001 task_id=1 business_object=对标账号 platform=小红书
account_identifier=xhs:acme_marketing is_benchmark=true is_ai_product=false
collected_at=2026-08-25 10:00:00 window_start=2026-08-24 00:00:00
raw_content="企业获客的三个误区"
structured_data={"title":"企业获客的三个误区","published_at":"2026-08-25T10:00:00+08:00"}
```

## 四、用例 AC-TC-02：记录级失败与部分成功

### 场景

小红书来源正常返回，视频号来源超时；操盘手只重试失败记录。

### 前置条件

任务配置同 AC-TC-01；记录 9001 可成功，记录 9002 的来源暂时超时。

### 操作步骤

1. 启动任务。
2. 等待 9001 成功、9002 超时。
3. 查看任务详情和记录列表。
4. 点击 9002 的记录级重试，不重试 9001。
5. 第二次仍超时，查看旧尝试。

### 预期结果

9001 生成结果 70001 并保持成功；9002 第一次失败并保存超时错误；任务进入 `部分成功`，该状态为新增建议，待确认；重试只处理 9002，不复制 70001；两次错误都可查。

### 关键数据示例

```text
collection_task:
task_no=CT20260826-001 status=部分成功 total_count=2 success_count=1 failure_count=1

collection_record 9001:
status=成功 attempt_no=1 item_count=2 error_message=NULL

collection_record 9002:
status=失败 attempt_no=2 error_code=SOURCE_TIMEOUT
error_message="source request timed out" retryable=true

collection_result:
record_id=9001 result_id=70001 is_ai_product=false
record_id=9002 无成功结果，不写入空结果
```

## 五、用例 AC-TC-03：任务级失败与重试

### 场景

任务初始化时授权配置无效，整个任务无法建立来源连接；修正外部配置后管理员重试。

### 前置条件

任务已创建为待执行，来源初始化返回 `AUTH_UNAVAILABLE`。授权凭据不写入文档或日志。

### 操作步骤

1. 点击开始采集。
2. 初始化失败，查看任务详情。
3. 管理员修正外部授权配置。
4. 点击任务级重试。
5. 检查重试后的任务和记录。

### 预期结果

原任务进入 `失败`，保存任务级错误和时间；不产生伪造成功结果；重试动作可追踪且旧错误保留；重试成功后按账号生成记录并继续正常流程；重试上限和复用原任务方式为新增建议，待确认。

### 关键数据示例

```text
collection_task:
task_no=CT20260826-002 status=失败 retry_count=1
error_message="source authorization unavailable"

retry_attempt（新增建议，待确认）:
attempt_no=1 result=failed error_code=AUTH_UNAVAILABLE
attempt_no=2 result=started
```

## 六、用例 AC-TC-04：重复任务提示与幂等

### 场景

管理员误以为第一次采集没有开始，再次提交相同账号、时间窗和范围。

### 前置条件

已有任务 `CT20260826-001`，账号集合 `[101,102]`，范围 `benchmark_account`，时间窗为 `2026-08-24 00:00:00` 至 `2026-08-25 23:59:59`，状态已完成。

### 操作步骤

1. 重新选择账号 101、102。
2. 输入相同时间窗和范围。
3. 点击创建任务。

### 预期结果

系统计算相同的建议幂等条件；页面提示已有任务 `CT20260826-001`、状态已完成和结果数量 2；默认提供“查看已有任务”，不再次调用来源；不覆盖旧任务和结果；强制创建策略、幂等键算法待确认。

### 关键数据示例

```text
idempotency_key=benchmark_account:101,102|benchmark_account|2026-08-24T00:00:00+08:00|2026-08-25T23:59:59+08:00
duplicate_task_id=1 duplicate_task_no=CT20260826-001
new_task_created=false
```

`idempotency_key` 是新增建议，待确认，不是一期已确认字段。

## 七、用例 AC-TC-05：结果进入资料库/分析链路

### 场景

操盘手查看一条原始内容，先沉淀为资料，再作为数据分析输入；系统可选生成 AI 摘要。

### 前置条件

结果 `70001` 已成功入库：`business_object=对标账号`、`platform=小红书`、`account_identifier=xhs:acme_marketing`、`is_benchmark=true`、`is_ai_product=false`，且有来源 URL。

### 操作步骤

1. 打开结果详情，核对原始内容和来源 URL。
2. 点击“沉淀到资料库”。
3. 填写或确认资料分类、可信度、有效期等资料字段。
4. 查看资料关联的采集结果。
5. 选择“作为分析输入”，创建分析任务。
6. 如执行 AI 摘要，打开摘要和原文对比。

### 预期结果

资料对象按 `context/05` 的资料分类、来源类型、来源链接、可信度、有效期处理；资料不把原始事实改写为 AI 产物；采集结果保持 `is_ai_product=false`；AI 摘要单独保存并为 `is_ai_product=true`；分析任务遵循 R6/R7 及审核变更说明。

### 关键数据示例

```text
collection_result 70001:
raw_content="企业获客的三个误区"
is_ai_product=false
source_url=https://example.invalid/xhs/acme_marketing/post/123

material（字段按一期资料口径）:
title="对标账号：企业获客的三个误区"
source_type=对标
source_link=https://example.invalid/xhs/acme_marketing/post/123
is_ai_product=false
source_collection_result_id=70001（新增建议，待确认）

ai_derivative（新增建议，待确认）:
source_record_id=9001
summary="内容聚焦企业获客常见误区"
is_ai_product=true
```

## 八、用例 AC-TC-06：停用账号

### 场景、操作和预期

操盘手将账号 103 设置为 `enabled=false`。新建任务搜索“已停用示例”时不出现在可选列表；打开历史任务时仍能看到 103 的记录和结果；若待执行任务包含 103，开始前重新校验并提示账号已停用。是否允许显式确认继续待确认。
