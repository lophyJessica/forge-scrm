# 自动采集_业务流程推演

> 文件定位：自动采集模块动态沙盘——主流程、异常分支、状态和数据链路推演
> 依据：自动采集主PRD、自动采集_业务规则规格、`context/04`、`context/05`
> 推演关卡：覆盖账号维护、人工触发、执行、独立落库、使用链路和异常分支后，才进入后续页面设计。

## 一、推演前提

当前使用人：操盘手（管理员）。

| account_identifier | account_name | platform | benchmark_flag | enabled |
|---|---|---|---|---|
| xhs:acme_marketing | 增长研究所 | 小红书 | true | true |
| wx:brand_lab | 品牌实验室 | 视频号 | true | true |
| xhs:old_account | 已停用示例 | 小红书 | true | false |

示例时间窗：`2026-08-24 00:00:00` 至 `2026-08-25 23:59:59`。时区为示例值，最终口径待确认。

## 二、主流程步骤推演

### 步骤 1：维护对标账号

入口：登录 → 左侧菜单“自动采集” → “对标账号管理”。

操作：点击新增，填写平台“小红书”、账号标识 `xhs:acme_marketing`、展示名称“增长研究所”、主页 URL，保存。

预期：校验必填项；保存为启用对标账号；`benchmark_flag=true`；新账号可被采集任务选择。账号唯一约束为新增建议，待确认。

### 步骤 2：选择账号与采集范围

入口：自动采集 → 新建采集任务。

操作：勾选“增长研究所”和“品牌实验室”，选择范围“对标账号内容与可用数据”，填写时间窗。

预期：停用账号不出现在可选列表；对标账号为默认优先范围；评论、热点、行业报告作为次优先范围展示，未实测来源不可假装可执行；提交前校验账号、时间窗和范围。

### 步骤 3：人工触发创建任务

操作：点击“创建任务”。

```text
task_no=CT20260826-001
trigger_type=manual
status=待执行
scope_type=benchmark_account
time_window_start=2026-08-24 00:00:00
time_window_end=2026-08-25 23:59:59
total_count=0 success_count=0 failure_count=0
```

预期：任务只创建不执行，页面提供“开始采集”按钮，符合 R13/AC-R2。

### 步骤 4：开始采集与记录拆分

操作：点击“开始采集”。

预期：任务从待执行进入执行中；按账号/来源创建 `record_id=9001` 和 `record_id=9002`；按钮 loading 防重复点击；每条记录保留任务、账号、来源 URL、请求时间和尝试序号。

### 步骤 5：调用来源并保存原始事实

成功响应示例：

```text
record_id=9001 status=成功 item_count=2
source_url=https://example.invalid/xhs/acme_marketing/post/123
raw_response={"items":[{"title":"企业获客的三个误区","published_at":"2026-08-25T10:00:00+08:00"},{"title":"客户案例拆解","published_at":"2026-08-24T16:20:00+08:00"}]}
```

预期：生成独立采集结果 `result_id=70001/70002`，写入原始内容和结构化数据，`is_ai_product=false`，保留任务、记录、账号、平台、来源 URL 和时间窗关联。

### 步骤 6：任务完成与查看

```text
task_no=CT20260826-001
status=已完成 total_count=2 success_count=2 failure_count=0
finished_at=2026-08-26 09:15:00
```

预期：任务列表可按已完成筛选；详情可查看每条记录和结果；原始事实不进入 AI 审核阻塞队列。

### 步骤 7：摘要与使用链路

操盘手先查看原始内容，再选择：

1. 沉淀到资料库：按资料分类、来源类型、来源链接、可信度、有效期和状态处理，目标映射待确认。
2. 作为分析输入：创建或选择分析任务，沿用数据分析输入关联和 R6/R7。
3. 生成摘要：摘要不得覆盖原文，`is_ai_product=true`，保留 `source_record_id`；字段为新增建议，待确认。

## 三、异常分支推演

### 分支 A：账号停用

前置：`xhs:old_account.enabled=false`。

预期：新任务不可选择停用账号；历史任务和结果仍可查询；若待执行任务包含该账号，开始前重新校验并提示“账号已停用”。是否允许管理员显式确认继续，待确认。

### 分支 B：来源不可达

官方 API 超时或来源不可访问时：任务保持可追踪，相关记录进入失败，保存 `error_code=SOURCE_UNREACHABLE`（错误码为新增建议，待确认）、错误信息、响应状态和尝试序号；不写入空的成功结果；全部失败时任务进入失败，管理员可任务级重试。

### 分支 C：一个账号失败、另一个成功

小红书记录成功、视频号记录解析失败时：成功结果立即可查，失败记录保留错误，任务进入“部分成功”（新增建议，待确认）；操盘手只能重试失败记录，不能重复写入成功账号结果。

### 分支 D：重复任务

已有任务 `CT20260826-001` 且账号集合、时间窗和范围完全相同时：再次创建展示已有任务编号、状态和结果数量，默认引导打开旧任务，不重复调用来源；强制创建策略待确认。

### 分支 E：网页抓取不合规

来源 robots 或服务条款禁止自动化访问时：显示明确不可执行/失败提示，不尝试绕过限制，不以“采集成功 0 条”表示成功；具体合规判定流程待实测。

## 四、页面与状态对应关系

| 页面/区域 | 主要实体 | 主要状态/动作 |
|---|---|---|
| 对标账号管理 | 对标账号 | 启用/停用/新增/编辑 |
| 新建采集任务 | 采集任务 | 创建后待执行 |
| 任务列表 | 采集任务 | 待执行/执行中/已完成/部分成功/失败 |
| 任务详情 | 采集任务、采集记录 | 进度、错误、任务级重试 |
| 采集记录列表 | 采集记录 | 成功/失败、来源、记录级重试 |
| 采集结果详情 | 采集结果 | 原始内容、结构化内容、追溯链 |
| 资料库使用动作 | 采集结果→资料 | 沉淀/关联；目标状态待确认 |
| 数据分析使用动作 | 采集结果→分析任务 | 输入关联；目标模块规则生效 |

## 五、状态快照推演

### 快照 1：任务创建后

```text
task=CT20260826-001 status=待执行
├─ account=xhs:acme_marketing record=9001 status=待执行
└─ account=wx:brand_lab record=9002 status=待执行
```

### 快照 2：一条成功、一条失败

```text
task=CT20260826-001 status=部分成功（新增建议，待确认）
├─ record=9001 status=成功 result=70001/70002 is_ai_product=false
└─ record=9002 status=失败 error=PARSE_ERROR attempt_no=1
```

### 快照 3：只重试失败记录

```text
record=9002 attempt_no=2 status=失败 error=SOURCE_TIMEOUT
record=9001 status=成功 result=70001/70002（不重复创建）
task=CT20260826-001 status=部分成功（待确认）
```

### 快照 4：全部成功

```text
record=9002 attempt_no=3 status=成功 result=70003
task=CT20260826-001 status=已完成 success_count=2 failure_count=0
```

## 六、流程走查清单

- [ ] 停用账号不能进入新任务，历史结果可查。
- [ ] 创建任务不会隐式启动，开始采集需要人工点击。
- [ ] 对标账号为默认优先采集对象。
- [ ] 任务、记录、结果独立落库并可回溯。
- [ ] 原始内容和结构化数据同时可查，原始事实不被摘要覆盖。
- [ ] 原始采集结果默认 `is_ai_product=false`。
- [ ] 任务级失败与记录级失败可区分。
- [ ] 部分成功能查看成功结果并只重试失败记录。
- [ ] 重试不覆盖旧错误、不重复写入成功结果。
- [ ] 重复任务有提示，不默认重复调用来源。
- [ ] 资料库和数据分析使用动作回到目标模块规则。
- [ ] 合规不可采集时不伪造成功、不绕过限制。

## 七、待确认事项

1. 任务创建后账号被停用时，是否允许已创建任务继续执行。
2. 来源失败错误码和记录状态枚举待确认。
3. 部分成功的数据库状态或 DTO 表达待确认。
4. 任务级重试和记录级重试的尝试表/计数实现待确认。
5. 采集结果进入资料库的页面动作和默认资料状态待确认。
6. AI 摘要默认开关、异步时机和抽查策略待确认。
7. 官方 API 与网页来源的合规和字段实测待确认。
