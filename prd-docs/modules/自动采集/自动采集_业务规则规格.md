# 自动采集_业务规则规格

> 文件定位：自动采集模块规则、状态、校验和异常处理规格
> 依据：`context/04-业务规则与状态机.md`、`context/05-术语与字段口径.md`、`requirements/09-二期调研结论.md`
> 规则约定：一期规则沿用 `R1-R20`；本模块新增规则使用 `AC-R` 前缀。新增实体、字段、状态、枚举和配置均为“新增建议，待确认”。

## 二、一期规则引用

### 2.1 R13：人工触发

`context/04` 的 R13 规定自动采集未来启用时采用人工触发，一期不做定时任务。二期将自动采集纳入 P0，但仍要求用户先创建任务，再明确点击开始采集。定时采集仅列为 P1 预留，不定义频率、调度器、时区、暂停或告警配置。

### 2.2 R16：采集方式演进

R16 的一期口径是没有视频号账号，自动采集仅预留，MVP 以手动录入和 CSV/TXT 导入为主。二期依据 09 调研结论启用自动采集，但不回写 `context/04`。平台能力、账号授权和可采集指标需要实测。

### 2.3 R8：原始事实与 AI 产物

采集来源返回的内容和指标属于原始事实；解析、字段标准化、去重属于数据处理，不改变事实属性。AI 摘要、分类、标签建议、趋势判断或生成结论属于 AI 产物，必须有 `is_ai_product=true` 或等价标识，并保留原始结果关联。

二期“原始采集数据直接信”不等于跳过来源、完整性和合规检查，也不允许用 AI 结果覆盖原始内容。AI 衍生内容保留轻量抽查，具体比例和触发时机见审核变更说明并标注待确认。

### 2.4 R1/R2：沉淀资料

采集结果原始表不直接冒充资料条目。若操盘手选择沉淀到资料库，需遵循资料分类、来源类型、来源链接、可信度、有效期和状态口径。是否创建资料后默认生效，取决于二期默认通过映射，当前为新增建议，待确认。

### 2.5 R6/R7：进入分析

采集结果可作为数据分析任务输入。分析任务仍保留结构化输出校验、原始响应、审核/默认通过和回写/反哺字段；本模块不建立新的分析契约。

### 2.6 R4/R14：去重边界

本模块可记录数据清洗/去重信息，但不承诺语义去重。采集结果被选题链路使用时，选题完全重复去重继续遵循 R4/R14；采集结果自身的幂等和重复任务提示属于 AC-R8。

## 三、采集对象与来源规则

### AC-R1 对标账号优先

1. 默认任务优先展示和选择对标账号。
2. 对标账号数据包括可获得的账号信息、更新内容、发布时间、选题和平台表现数据。
3. 评论、热点和行业报告保持采集入口，但为次优先对象。
4. 采集范围采取“先全量给，用后再收敛”，上线后用真实使用反馈和行为数据收敛对象及字段。
5. 播放量、点赞、评论、涨粉等指标不作为一期固定列，优先放入 `structured_data`，待实测后决定拆列。

### AC-R2 人工触发与 P1 定时预留

1. 创建任务不自动开始采集。
2. 只有具备权限的用户点击开始后，任务才能从待执行进入执行中。
3. 执行中的任务不能被重复点击创建第二次执行。
4. 定时触发属于 P1，仅允许在范围中出现预留描述，不作为 P0 验收项。

## 四、来源接入与合规规则

### AC-R3 官方 API 优先

来源接入按以下优先级评估：官方 API 或授权接口；来源方允许的公开数据接口；经过合规和工程评审允许的网页公开内容读取。登录后内容、验证码保护内容、付费墙内容和明确禁止自动化访问的内容不作为默认采集能力。

官方接口可用性、OAuth/授权方式、配额、字段完整度、分页、历史回溯范围、失败码、服务条款、robots、访问频率、版权、存储期限和删除请求均待实测/待确认。

### AC-R4 网页抓取边界

若网页抓取进入实测，必须检查：

| 检查项 | 规则 | 确认度 |
|---|---|---|
| robots | 遵守来源声明；禁止路径不访问 | 待实测/待确认 |
| 服务条款 | 不违反来源服务条款和平台规则 | 待实测/待确认 |
| 频率 | 设置来源可接受的访问频率和并发 | 待实测/待确认 |
| 版权 | 只保存必要内容，保留来源和使用范围 | 待实测/待确认 |
| 登录/风控 | 不绕过验证码、登录限制或风控 | 已确认边界 |
| 失败显示 | 不可合法采集时明确显示失败 | 新增建议，待确认 |

## 五、任务、记录和重试规则

### AC-R5 任务创建校验

| 校验 | 规则 | 结果 |
|---|---|---|
| 账号集合 | 至少一个启用对标账号 | 不通过则不创建任务 |
| 时间窗 | 开始时间不晚于结束时间 | 不通过则提示并不创建 |
| 采集范围 | 必须选择已支持或实测可用范围 | 不支持则阻止执行 |
| 权限 | 沿用现有授权 | 无权限拒绝 |
| 合规状态 | 来源被判定不可采集时不得开始 | 任务失败或不可执行提示 |

以上新增校验字段和错误码为新增建议，待确认。

### AC-R6 追溯链

每个成功或失败的采集动作应能按以下方向回看：

`采集结果 → 采集记录 → 采集任务 → 对标账号/来源 → 平台/来源 URL/时间窗`

结果必须保留原始内容或对象存储引用、结构化内容、采集时间、任务时间窗和来源标识。非账号来源时对标账号外键可为空。字段名、存储方式和关联表为新增建议，待确认。

### AC-R7 任务级失败

任务级失败是无法建立或执行整个任务的情况，例如配置不可解析、来源连接初始化失败、授权不可用或系统级异常。

1. 任务保留为失败状态。
2. 记录任务级错误码、错误信息和发生时间。
3. 未创建有效记录的部分不得伪装为成功。
4. 用户可从任务详情发起任务级重试。
5. 重试创建新尝试或更新尝试计数的方式待确认，但不能删除旧错误。

### AC-R8 记录级失败与部分成功

记录级失败是任务已启动但某个账号/来源调用失败、解析失败或内容校验失败。

1. 该记录单独保存失败原因、来源响应状态和尝试序号。
2. 其他记录继续执行，不因单条失败中断整个任务。
3. 至少一条成功且至少一条失败时，任务进入“部分成功”；该状态为新增建议，待确认。
4. 用户可以只重试失败记录，成功结果不重复入库。
5. 记录级重试失败仍保留每一次尝试的错误，不能覆盖原响应。

### AC-R9 重试上限与幂等

重试上限、退避时间、是否人工确认每次重试、任务级和记录级尝试表是否拆分，均为新增建议，待确认。已确认的产品行为是：重试可追踪、成功结果不重复生成、旧错误不丢失。

## 六、重复任务提示

### AC-R10 幂等条件

建议使用以下组合判断重复任务：

`启用账号集合 + 来源/采集范围 + 时间窗开始 + 时间窗结束`

组合键和规范化算法为新增建议，待确认。发现相同任务时：

1. 提示已有任务编号、状态、创建时间和结果计数。
2. 默认引导用户打开已有任务，避免重复消耗来源配额。
3. 不覆盖旧任务和旧结果。
4. 是否允许管理员强制创建新任务、是否需要强制原因待确认。

## 七、结果使用与 AI 标记

### AC-R11 原始结果直接信

“直接信”指原始采集结果可以被查看和作为后续输入，不要求先通过 AI 审核。仍需完成来源合法性判断、响应完整性检查、任务/记录状态更新和来源追溯保存。原始结果默认 `is_ai_product=false`。

若原始结果进入资料库，资料自身状态、有效期和可信度仍按资料模块处理；二期默认通过变化不删除资料审核入口。

### AC-R12 AI 衍生结果

摘要、主题分类、趋势结论、标签建议、选题建议、脚本建议和分析结论若由模型生成，均属于 AI 产物。必须不覆盖原始内容、标记 `is_ai_product=true`、保留采集结果/任务/原始响应关联，并进入轻量抽查范围。抽查比例和触发时机待确认。

## 八、状态与权限

### 8.1 任务状态

| 状态 | 含义 | 确认度 |
|---|---|---|
| 待执行 | 创建完成未启动 | 与总 PRD 对齐；新增状态建议，待确认 |
| 执行中 | 正在采集 | 新增建议，待确认 |
| 已完成 | 全部记录成功 | 新增建议，待确认 |
| 部分成功 | 成功与失败记录并存 | 新增建议，待确认 |
| 失败 | 任务级失败或全部失败 | 新增建议，待确认 |

### 8.2 记录状态

待执行、执行中、成功、失败为建议表达，具体枚举为新增建议，待确认；若复用现有状态，必须保证记录级失败可查询。

### 8.3 权限规则

管理员可维护账号、创建/启动/重试任务和查看结果；成员是否能操作二期采集沿用现有功能权限，具体矩阵为新增建议，待确认。沉淀资料和创建分析任务还需通过目标模块已有权限。不建设多人协作、会签、分级审批或新的角色枚举。

## 十、待确认事项

1. 任务与记录最终状态枚举及“部分成功”是否写入数据库。
2. 任务级和记录级重试上限、退避时间和尝试表设计。
3. 官方 API、网页公开数据和报告来源的实际可采集范围。
4. robots、服务条款、版权、频率和数据存储合规结论。
5. 重复任务提示的强制创建策略和幂等键算法。
6. 采集结果进入资料库的具体操作、默认状态和回写关联。
7. AI 摘要是否默认生成、模型调用方式和抽查字段。
