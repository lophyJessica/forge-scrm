# 推送任务取消/删除 + 卡片内容闭环 — 迭代需求（v2 B 方案）

> 状态：已确认，待开发（v2：卡片方案从"跳转系统"改为"飞书内闭环展示全文"）
> 日期：2026-08-28
> 决策：用户拍板 B——**飞书的就在飞书闭环**，不跳转系统、不做登录引导。卡片本身承载报告全文。
> 背景：飞书推送上线实测通过。用户反馈：任务无法取消/删除；卡片内容不全且点击无响应。

## 任务一：推送任务取消/删除（主项）

### 现状

推送任务状态机：待推送 → 推送中 → 已推送/失败（retry_count 手动重试）。**没有任何取消或删除手段**——误建的任务永远挂在列表里。

### 需求

**1. 取消推送（状态操作）**
- 仅「待推送」「失败」状态可取消；「推送中」「已推送」不可取消
- 取消后状态置「已取消」（新增枚举值），取消即终态；想再推就新建任务
- 推送中状态禁止取消/删除（防发送中途产生脏状态）

**2. 删除推送任务（记录清理）**
- 仅「待推送」「失败」「已取消」状态可删除，删除任务及其 records
- 「推送中」不可删除；「已推送」作为发送和对账凭证不可删除
- 二次确认：Modal.confirm「确认删除该推送任务？删除后不可恢复」

**3. 后端接口**
- POST /api/reports/push-tasks/{task_id}/cancel —— 校验可取消状态，置「已取消」
- DELETE /api/reports/push-tasks/{task_id} —— 仅允许待推送/失败/已取消，删任务+records；推送中和已推送均拒绝
- 枚举扩展：ReportPushStatus 增加「已取消」（models/report.py；report_push_status 落库类型以现状为准最小处理——varchar 直接加值，native enum 则需 alembic 迁移）

**4. 前端（ReportDetail.tsx 抽屉内）**
- actions 按状态：待推送/失败 → [发送][取消][删除]；已取消 → [删除]；已推送 → 无操作
- 取消轻操作不二次确认；删除必须 Modal.confirm
- 已取消 Tag 灰色

### 验收
1. 待推送任务取消后状态变已取消、发送按钮消失
2. 待推送/失败/已取消任务二次确认后删除，records 同删，列表消失
3. 推送中任务取消/删除均被拒
4. 已推送任务作为发送凭证，前后端均不允许删除

## 任务二：卡片飞书内闭环展示（B 方案）

### 需求

卡片重构为「通知 + 全文」双层结构，用户不离开飞书即可读完报告：

**1. 折叠层（默认展开）：概览**
- 保留现有：标题（header）、生成时间、摘要（800 字截断）
- 新增数据概览行：来源数量/类型分布等报告实体现有关键字段（以 report 表字段为准，有则展示，无则略）

**2. 展开层：报告正文（lark_md，折叠在「查看完整报告」交互后）**
- 飞书卡片 md 元素支持折叠语法（`<details>` 在 lark_md 不可用，用卡片 column_set 或多个 elements + `折叠` 交互组件——**以飞书卡片搭建器当前支持的组件为准**：若 md 折叠不可用，用「点击展开」的 collapsible panel 组件；再不行则正文直接平铺但限长）
- 正文来源：report.content 或 report.summary 之外的完整正文字段（以 report 实体现有字段为准），超长截断到**飞书单卡片总上限内**（卡片 JSON 整体 < 30KB；正文超限则截断并注「完整报告见系统」）
- 正文含 markdown 结构（标题/列表/来源清单），lark_md 语法转换注意：标准 md 大部分兼容，表格需转列表

**3. 兜底跳转（不强制）**
- 正文超限截断时，卡片底部加一行小字：「正文超长已截断，完整内容请登录系统查看」——纯文字提示，不做按钮

### 技术要点

- send_report_card 增加 report_body 参数（reports.py 调用时传 report 正文）；_report_card 组装全文
- 正文转 lark_md：后端做简单替换（## → **粗体**、- 保留、表格行转列表），不自建复杂解析器
- 卡片 JSON 体积校验：超 28KB 截断正文并追加提示行

### 验收
1. 新推送卡片默认显示标题+时间+摘要+概览
2. 展开后能读到报告全文（或超长截断版+提示）
3. 姐夫全程不离开飞书即可了解报告核心内容
4. 卡片在手机端飞书展示正常（body 结构简单，无固定宽度元素）

## 边界

- 不做免登录分享/跳转系统链接（B 方案核心：不跳）
- 不做消息撤回/卡片更新（发后即终）
- 不做批量操作

## 验收总清单（用户亲测）

1. 误建任务可取消，终态不可再发送
2. 仅未发送成功的待推送/失败/已取消任务可二次确认后删除，已推送凭证不可删除
3. 新卡片在飞书内可读全文，无需跳转
