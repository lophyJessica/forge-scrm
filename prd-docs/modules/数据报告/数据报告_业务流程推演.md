# 数据报告_业务流程推演

> 文件定位：数据报告模块动态沙盘——报告生成、审核抽查、推送和资料沉淀链路
> 依据：数据报告主PRD、数据报告字段清单、数据报告_业务规则规格、二期总 PRD 5.3
> 推演关卡：覆盖配置报告、触发生成、数据聚合、报告完成、默认通过/抽查、推送和沉淀后，才进入统一验收。

## 一、推演前提

当前使用人：操盘手（管理员）。

示例周期：`2026-08-17 00:00:00` 至 `2026-08-23 23:59:59`，时区为示例值，最终周周期口径待确认。

示例来源：

```text
analysis_result_id=4101 status=已确认
collection_result_id=70001 is_ai_product=false
research_report_id=RR20260826-001 is_ai_product=true
business_data_period=2026-08-17/2026-08-23
```

来源实体由一期、第二步和第三步模块负责；数据报告模块只引用来源，不重设计其表。

## 二、主流程步骤推演

### 步骤 1：配置报告

入口：登录 → 左侧菜单“数据报告” → “报告配置/新建报告”。

操作：选择报告类型“运营数据报告”，选择模板 `template_id=21`，设置周期、来源和输出范围。

预期：

1. 报告类型为统一报告实体的类型区分，最终枚举为新增建议，待确认。
2. 页面明确数据分析结果、运营业务数据和可用自动采集结果为主要来源。
3. 周期开始不得晚于周期结束。
4. 模板、周期配置和来源范围均可回看，字段为新增建议，待确认。

示例配置：

```text
report_type=运营数据报告
template_id=21
period_start=2026-08-17 00:00:00
period_end=2026-08-23 23:59:59
source_config.analysis_result_ids=[4101]
source_config.collection_result_ids=[70001]
source_config.business_data=true
```

### 步骤 2：创建并触发生成

操作：点击“创建报告”，再点击“生成”。

预期：

1. 创建实例 `RP20260826-001`，状态为 `待生成`。
2. 明确点击生成后进入 `生成中`，不因打开页面而隐式生成。
3. 生成中的按钮防重复触发。
4. 任务展示报告类型、周期和来源数量。

### 步骤 3：数据聚合

运营数据报告聚合：

1. 读取数据分析结果 4101 的已确认输出。
2. 读取运营业务数据周期内的可用数据。
3. 读取采集结果 70001 的可用原始事实或结构化数据。
4. 保存来源快照和数据口径。

预期：来源读取失败时记录来源缺口，不用模型猜测补齐指标；数据指标和计算公式为新增建议，待确认。

### 步骤 4：生成报告

系统根据模板和聚合数据生成摘要、正文、章节、指标表和结论。

示例完成数据：

```text
report_no=RP20260826-001
report_type=运营数据报告
generation_status=已完成
review_status=默认通过
summary=本周内容产出与互动数据汇总
is_ai_product=true
generated_at=2026-08-26 10:30:00
```

预期：报告可查看，生成追溯可回看；AI 生成摘要/结论时 `is_ai_product=true`。纯聚合报告的例外标记待确认。

### 步骤 5：默认通过与轻量抽查

报告生成完成后进入二期默认通过路径，用户无需逐条审核即可查看和进入推送/沉淀动作。

抽查路径：

1. 系统或管理员将报告置于抽查中。
2. 检查来源是否完整、数据口径是否可解释、结论是否与来源一致、消息是否含敏感信息。
3. 抽查通过进入已确认或保持可用。
4. 发现问题转待审核、废弃或重新生成。

抽查比例、触发时间和状态写入方式为新增建议，待确认；抽查不修改原始数据分析结果、采集结果和业务数据。

### 步骤 6：创建推送任务

操作：在完成报告详情点击“推送”，选择“飞书”、目标类型“群”、目标标识 `feishu:group-demo`，确认消息摘要。

预期：

1. 只有已完成报告可以创建推送任务。
2. 任务 `PT20260826-001` 为 `待推送`。
3. 页面展示渠道、指定人/群、报告周期和消息摘要。
4. 渠道 API、授权和目标校验在实际接通前均待实测/待确认。

### 步骤 7：推送

操作：点击发送。

预期：任务进入 `推送中`；渠道明确确认成功后进入 `已推送`。如果返回限流、超时或授权错误，进入 `失败`，记录错误码并允许重试。报告状态不回滚。

### 步骤 8：查看和沉淀

操盘手可以：

1. 查看报告摘要、正文、周期、来源和生成时间。
2. 查看推送记录中的渠道、目标、摘要、发送时间和状态。
3. 将报告沉淀为资料库条目，填写一期资料分类、可信度、有效期和来源链接。
4. AI 报告沉淀资料 `is_ai_product=true`，保留报告来源关联。
5. 后续研究助手引用该资料，按第三步研究引用关系回点。

## 三、市场分析周报分支

### 步骤 9：配置市场分析周报

选择 `report_type=市场分析周报`，来源包括研究报告 `RR20260826-001`、采集结果 `70001` 和已实测外部检索来源。

预期：页面提示市场分析以趋势、竞对动态和未知变化为方向，结论结构不提前固定；外部检索源、版权和引用规则待实测。

### 步骤 10：生成与查看

报告生成后展示摘要、章节、结论和来源回点。报告含 AI 分析文字时 `is_ai_product=true`，默认通过可查看，抽查入口保留。

## 四、异常分支推演

### 分支 A：数据源不可用

前置：数据分析结果接口、业务数据或自动采集结果暂时不可用。

预期：

1. 报告实例保留失败来源和错误信息。
2. 缺失来源不被模型猜测填充。
3. 生成策略是失败、部分数据报告或等待补齐，具体策略待确认。
4. 成功读取的来源快照可复用，报告未完成前不进入默认通过。

### 分支 B：报告生成失败

前置：模型超时、输出结构缺失或来源校验失败。

预期：

1. 报告状态进入 `失败`，记录 `error_code`、错误说明和重试次数。
2. 不显示默认通过或已完成报告。
3. 管理员点击重试，保留旧错误和来源配置。
4. 成功后进入已完成和默认通过路径；重试上限、退避和幂等策略待确认。

### 分支 C：推送失败

前置：飞书/微信返回授权不足、目标不存在、超时或消息格式错误。

预期：

1. 推送任务进入失败，推送记录保存渠道、目标、摘要、发送时间、状态和错误码。
2. 报告继续保持已完成及其审核状态。
3. 用户可修正目标或授权后重试。
4. 失败和成功尝试均可追溯，不重复发送已经成功的目标。

### 分支 D：渠道限流

前置：渠道返回频率限制。

预期：显示“渠道限流”及渠道错误码；不把请求已发出视为已推送；按待确认的退避和重试策略处理。具体频率、配额和退避待实测。

### 分支 E：目标授权不足

前置：用户选择的飞书群或微信个人不在应用授权范围内。

预期：发送前或发送时失败，保留目标和授权错误；不保存凭据；调整授权后可重试，报告正文不受影响。

## 五、页面与状态对应关系

| 页面/区域 | 主要实体 | 状态/动作 |
|---|---|---|
| 报告配置 | 报告模板 | 类型、周期、来源和输出结构 |
| 报告列表 | 报告 | 待生成/生成中/已完成/失败 |
| 报告详情 | 报告 | 摘要、正文、章节、来源、生成/重试 |
| 审核区域 | 报告 | 默认通过/抽查中/已确认/待审核/已废弃 |
| 推送创建 | 推送任务 | 渠道、目标人/群、消息配置 |
| 推送记录列表 | 推送记录 | 待推送/推送中/已推送/失败、重试 |
| 资料沉淀动作 | 报告→资料 | 一期字段、可信度、有效期、AI 标记 |
| 研究引用动作 | 报告/资料→研究助手 | 后续模块引用，不重设计研究实体 |

## 六、状态快照推演

### 快照 1：报告待生成

```text
report=RP20260826-001
report_type=运营数据报告
generation_status=待生成
review_status=未进入审核
period=2026-08-17/2026-08-23
```

### 快照 2：生成中

```text
report=RP20260826-001 generation_status=生成中
source_count=3 progress_message=正在聚合分析结果和业务数据（字段待确认）
```

### 快照 3：默认通过可查看

```text
report=RP20260826-001 generation_status=已完成
review_status=默认通过 is_ai_product=true
summary=本周内容产出与互动数据汇总
```

### 快照 4：推送失败

```text
push_task=PT20260826-001 status=失败
├─ channel=飞书 target_object=feishu:group-demo
└─ push_record status=失败 error_code=RATE_LIMITED attempt_no=1
report=RP20260826-001 generation_status=已完成 review_status=默认通过
```

### 快照 5：推送成功并沉淀

```text
push_task=PT20260826-001 status=已推送 retry_count=1
push_record attempt_no=2 status=已推送 sent_at=2026-08-26 10:45:00
material_id=601 is_ai_product=true source_report_id=RP20260826-001（待确认）
```

## 七、流程走查清单

- [ ] 运营数据报告和市场分析周报可按类型区分。
- [ ] 报告配置包含周期、来源和模板，具体配置标注待确认。
- [ ] 报告生成状态为待生成→生成中→已完成/失败，失败可重试。
- [ ] 运营数据来源包含分析结果、业务数据和可用采集结果。
- [ ] 市场分析来源包含研究助手报告、采集结果和外部检索。
- [ ] 来源不可用时不以模型猜测伪装完整数据。
- [ ] 完成报告默认可查看，AI 内容标记 `is_ai_product=true`。
- [ ] 轻量抽查入口保留，抽查不覆盖原始来源。
- [ ] 推送状态为待推送→推送中→已推送/失败，失败可重试。
- [ ] 飞书/微信推送保留渠道、目标、摘要、时间、状态和错误码。
- [ ] 推送失败不回滚报告，成功目标不重复发送。
- [ ] 报告沉淀资料遵循一期字段并保留研究助手可引用关系。

## 八、待确认事项

1. 报告类型、周期、时区、指标和来源字段最终口径。
2. 数据源不可用时采用失败、部分报告还是等待补齐。
3. 统一报告实体与报告模板的最终建模方式。
4. 默认通过/抽查的比例、时机、粒度和状态落库方式。
5. 飞书/微信 API、授权、限流、消息格式和错误码待实测。
6. 推送目标校验、多目标任务和失败隔离策略。
7. 推送全文、摘要、链接、图表和附件边界。
8. 报告沉淀资料和被研究助手引用的关联字段。
