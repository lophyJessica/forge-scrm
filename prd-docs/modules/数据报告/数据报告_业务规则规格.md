# 数据报告_业务规则规格

> 文件定位：数据报告模块周期生成、来源口径、审核抽查和渠道推送规则
> 依据：`context/04-业务规则与状态机.md`、`context/05-术语与字段口径.md`、`requirements/09-二期调研结论.md`
> 规则约定：一期沿用 `R1-R20`；本模块新增规则使用 `RPT-R` 前缀。新增实体、字段、状态、枚举和配置均为“新增建议，待确认”。

## 二、一期规则引用

### 2.1 R1/R2：报告沉淀资料

报告沉淀资料库时，目标资料继续使用一期已定义的标题、内容、资料分类、标签、来源类型、来源链接、可信度、有效期、状态、审核和创建追踪字段。报告是 AI 生成的内容时，目标资料 `is_ai_product=true`。报告本身是否保存可信度不替代资料可信度，是否新增报告评级字段待确认。

### 2.2 R6/R7：数据分析来源

运营数据报告可以引用分析结果和运营业务数据，市场分析周报可以引用研究助手报告、自动采集结果和外部检索来源。数据分析任务的状态、审核、回写和反哺仍遵循 R6/R7 及二期审核变更，不在本模块重定义分析实体。

### 2.3 R8：AI 产物标记

报告中的模型摘要、趋势判断、市场结论、建议和生成文字均是 AI 产物，默认 `is_ai_product=true`。原始运营数据、数据分析原始结果、第二步采集结果和第三步研究引用来源不因进入报告而变成 AI 产物。报告不得用 AI 结论覆盖来源事实。

### 2.4 R13/R17/R18/R20

- R13：定时采集不是本模块的 P0；报告周期触发的实现方式与采集调度分开，调度策略待确认。
- R17：运营指标和深度市场指标按真实来源迭代，不把未确认指标写为固定强制字段。
- R18/R20：沿用账号密码登录和现有角色边界，不新增多人订阅权限。

## 三、报告周期和类型规则

### RPT-R1 周期生成

1. P1 报告包含每周运营数据报告和每周市场分析周报。
2. 每个报告实例必须记录周期开始、周期结束和生成时间。
3. 推荐使用统一报告实体，通过 `report_type` 区分两类报告；实体、字段和枚举为新增建议，待确认。
4. 自然周/滚动七天、周起始日、时区、周期重叠和重复生成处理待确认。
5. 本模块可以提供手动触发入口，是否启用自动周期任务及其调度器待确认。

### RPT-R2 报告来源口径

| 报告类型 | 主要来源 | 口径规则 |
|---|---|---|
| 运营数据报告 | 数据分析结果、运营业务数据、可用自动采集结果 | 数据按报告周期聚合，指标计算公式和缺失处理待确认 |
| 市场分析周报 | 研究助手报告、自动采集结果、外部检索来源 | 结论必须尽量有引用，来源不可用要显式提示 |

来源配置、来源快照、数据时间窗、指标口径和来源关联字段均为新增建议，待确认。自动采集结果、研究助手报告和数据分析结果的原表不在本模块重设计。

### RPT-R3 来源先于结论

1. 报告生成前确认来源集合和时间窗。
2. 报告正文、表格或章节结论应能回到来源对象或来源快照。
3. 数据缺失、来源冲突或来源过期时，报告必须展示缺口或待核对提示。
4. 不以模型猜测填补缺失指标，不把不可访问来源显示为已验证事实。
5. 来源回点、快照和引用粒度为新增建议，待确认。

## 四、报告生成和错误规则

### RPT-R4 生成输入

报告生成任务读取模板、报告类型、周期、来源配置和可用数据。数据聚合和 AI 整理可拆为内部阶段，但本步对外统一使用待生成、生成中、已完成、失败四类状态；阶段字段是否新增待确认。

### RPT-R5 生成校验

生成完成前至少检查：

| 检查项 | 规则 | 确认度 |
|---|---|---|
| 报告类型 | 必须是已支持类型 | 新增枚举建议，待确认 |
| 周期 | 开始时间不晚于结束时间 | 新增配置建议，待确认 |
| 来源 | 来源配置可解析且有可用输入 | 新增校验建议，待确认 |
| 结构 | 摘要/正文基本结构存在 | 新增校验建议，待确认 |
| 口径 | 指标或结论有来源说明 | 新增校验建议，待确认 |
| AI 标记 | AI 内容标记 true；纯聚合例外待确认 | 引用 R8 |

### RPT-R6 生成失败重试

1. 数据源不可用、聚合异常、模型超时、输出结构缺失或来源校验失败时进入失败。
2. 失败任务保留来源配置、已获取输入、错误码、错误信息和重试次数。
3. 用户可以点击重试；重试不覆盖旧报告或旧错误。
4. 生成中禁止重复触发相同报告实例。
5. 重试上限、退避策略、是否复用已聚合数据和是否保留失败版本为新增建议，待确认。

## 五、审核默认通过与轻量抽查

### RPT-R7 默认通过

1. 报告生成完成后默认进入可查看/可使用路径，不强制用户逐条审核。
2. 报告审核状态按总 PRD 5.3 建议为默认通过、抽查中、已确认、待审核、已废弃；状态为新增建议，待确认。
3. 默认通过不删除人工审核入口；管理员可以主动发起审核或抽查。
4. 报告包含 AI 摘要、趋势、结论或建议时默认 `is_ai_product=true`。
5. 纯运营数据聚合是否允许 `is_ai_product=false`，以及聚合和 AI 混合时如何标记，待确认。

### RPT-R8 轻量抽查

1. 抽查对象：AI 生成的市场分析报告、AI 生成的运营报告文字、AI 结论和 AI 建议。
2. 原始运营数据、自动采集原始结果和数据分析原始输入不进入 AI 审核阻塞队列。
3. 抽查内容包括来源完整性、结论与来源一致性、明显事实错误和敏感信息。
4. 抽查通过进入已确认或保持可用；发现问题可转待审核、废弃或重新生成。
5. 抽查比例、触发时机、抽查粒度和字段承载方式待确认。
6. 抽查不能覆盖或删除原始来源、数据分析结果或采集结果。

## 六、推送合规和可追溯规则

### RPT-R9 渠道实测边界

飞书和微信是已确认的推送目标渠道，但以下能力全部待实测/待确认：

| 项目 | 要求 | 确认度 |
|---|---|---|
| API 能力 | 能否发送给指定人/群、是否支持链接/卡片 | 待实测 |
| 授权方式 | 应用授权、管理员授权和目标授权 | 待实测/待确认 |
| 频率限制 | 单次、单群、单应用频率和配额 | 待实测/待确认 |
| 消息格式 | 文本、卡片、链接、附件和长度 | 待实测/待确认 |
| 返回结果 | 消息 ID、成功码、失败码和错误信息 | 待实测/待确认 |
| 可见性 | 详情链接和内容访问范围 | 待实测/待确认 |

不得把某个渠道 SDK、域名、token 或连接配置写入本 PRD 作为已确认依赖。

### RPT-R10 目标授权

1. 推送任务只能选择用户明确指定的个人或群目标。
2. 发送前校验渠道和目标授权；校验方式待确认。
3. 目标不存在、被禁用、权限不足或不属于当前授权范围时，不发起或明确失败。
4. 目标对象的标识和类型需要记录，敏感凭据不保存到报告字段或推送记录。
5. 是否支持一个推送任务多个目标，及其失败隔离策略待确认。

### RPT-R11 消息最小化和敏感数据

推送默认只包含报告标题、类型、周期、摘要、生成时间和详情链接。原始数据、账号隐私、授权信息、内部错误堆栈、数据库信息、token、密码、API key 和连接串不得进入消息。全文、图表、附件和链接权限待确认。

### RPT-R12 推送状态、失败和重试

1. 推送任务按待推送→推送中→已推送/失败流转。
2. 成功以渠道明确确认或可验证响应为准，不能仅以本地请求发出视为成功。
3. 失败记录渠道、目标、消息摘要、发送时间（若有）、错误码、错误信息和尝试序号。
4. 失败可重试，成功发送不重复发送；幂等键为新增建议，待确认。
5. 限流、超时、授权失败和消息格式错误需区分显示；重试上限和退避待确认。
6. 推送失败不改变报告已完成、默认通过或已确认状态。

## 七、报告沉淀资料规则

报告沉淀资料时，目标模块规则优先：继续填写资料分类、来源类型、来源链接、可信度、有效期和状态；AI 报告标记 `is_ai_product=true`；保存报告和来源追溯。资料默认通过的状态映射依照审核流程变更说明，待回写/待确认，不在本模块新造资料状态。

## 八、权限规则

管理员可配置模板、生成/重试报告、查看报告、抽查、沉淀资料和创建推送；成员沿用现有授权，不新增多人订阅或 RBAC。飞书/微信连接配置和目标授权只能由具备权限的管理员使用，具体权限字段待确认。

## 十、待确认事项

1. 周起始日、时区、自然周/滚动周期和重复周期规则。
2. 统一报告实体+`report_type`还是拆分两类报告表。
3. 运营数据报告指标集合、公式、缺失数据处理和来源快照。
4. 市场分析周报章节、未知变化定义和引用缺失策略。
5. 报告 AI 标记的纯聚合例外和混合内容判定。
6. 默认通过和轻量抽查的具体状态、比例、时机和抽查字段。
7. 报告生成重试上限、退避和幂等策略。
8. 飞书/微信 API、授权、频率、消息格式和返回码实测。
9. 推送目标人/群校验、多个目标失败隔离和凭据保管方式。
10. 推送消息的摘要、全文、链接、图表、附件和可见范围。
11. 推送错误码、重试上限、重复发送幂等和限流退避。
