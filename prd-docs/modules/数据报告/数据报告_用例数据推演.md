# 数据报告_用例数据推演

> 文件定位：数据报告模块强制关卡——带字段值、状态快照和报告/推送链路的用例推演
> 配套：数据报告主PRD、数据报告字段清单、数据报告_业务规则规格、数据报告_业务流程推演
> 通过条件：周报生成、生成失败重试、飞书成功/失败重试、微信成功/失败重试、资料沉淀/研究助手引用五类用例均可闭环。

## 一、数据基线

### 1.1 来源样例

```text
analysis_result_id=4101 task_type=数据分析 status=已确认
collection_result_id=70001 business_object=对标账号 platform=小红书
research_report_id=RR20260826-001 is_ai_product=true
business_data_period=2026-08-17 00:00:00 至 2026-08-23 23:59:59
```

以上来源实体由一期、第二步和第三步模块负责，本模块只引用，不重设计其字段。

### 1.2 报告配置样例

```json
{
  "report_type": "运营数据报告",
  "period_start": "2026-08-17T00:00:00+08:00",
  "period_end": "2026-08-23T23:59:59+08:00",
  "template_id": 21,
  "source_config": {
    "analysis_result_ids": [4101],
    "collection_result_ids": [70001],
    "research_report_ids": [],
    "business_data": true
  }
}
```

> `report_type`、周期配置、模板和来源 JSON 均为新增建议，待确认；时间时区为示例值。

## 三、用例 RPT-TC-01：周报生成全流程

### 场景

操盘手查看 2026-08-17 至 2026-08-23 的运营数据报告，了解本周内容和可获得的运营数据。

### 前置条件

1. 管理员已登录。
2. 数据分析结果 4101 已完成/已确认。
3. 业务数据已按示例周期提供。
4. 自动采集结果 70001 可作为补充来源。
5. 报告模板 21 已启用；模板实体和具体配置为新增建议，待确认。

### 操作步骤

1. 进入数据报告，选择“运营数据报告”。
2. 选择模板 21，确认周期和来源。
3. 创建报告实例，检查状态为 `待生成`。
4. 点击生成，检查状态为 `生成中`。
5. 系统聚合分析结果、业务数据和采集结果。
6. 生成摘要、正文和可用指标，检查状态为 `已完成`。
7. 按二期规则查看默认通过报告。

### 预期结果

1. 生成报告 `RP20260826-001`，类型为运营数据报告。
2. 报告周期和来源配置可查看。
3. 报告包含摘要、正文、来源口径和生成时间。
4. 报告默认可查看；如果正文含 AI 生成结论，`is_ai_product=true`。
5. 原始数据和分析结果保持原实体语义，不被报告覆盖。
6. 报告可进入轻量抽查，抽查不是查看前置阻塞。

### 关键数据示例

```text
report:
report_no=RP20260826-001 report_type=运营数据报告
period_start=2026-08-17 00:00:00 period_end=2026-08-23 23:59:59
template_id=21 generation_status=已完成 review_status=默认通过
summary=本周内容产出与互动数据汇总
is_ai_product=true generated_at=2026-08-26 10:30:00
source_config={"analysis_result_ids":[4101],"collection_result_ids":[70001],"business_data":true}
```

## 四、用例 RPT-TC-02：报告生成失败与重试

### 场景

市场分析周报生成期间，研究助手来源不可用或 AI 输出结构校验失败；管理员修正来源后重试。

### 前置条件

1. 选择报告类型“市场分析周报”。
2. 研究报告 `RR20260826-001` 和采集结果 70001 已在来源配置中。
3. 某外部来源返回超时，或生成输出缺少正文。

### 操作步骤

1. 创建 `RP20260826-002` 并点击生成。
2. 查看生成状态和错误详情。
3. 确认已保存的来源快照仍在。
4. 修正来源或等待服务恢复，点击重试。
5. 查看新生成的摘要、正文和结论。

### 预期结果

1. 失败实例状态为 `失败`，保存错误码、错误说明、来源配置和重试次数。
2. 失败实例不能显示为已完成或默认通过。
3. 重试不覆盖旧错误；成功后状态为 `已完成`，审核状态进入默认通过路径。
4. 已聚合的数据或来源快照按可用策略复用；复用方式待确认。
5. 失败不影响其他已完成报告。

### 关键数据示例

```text
report:
report_no=RP20260826-002 report_type=市场分析周报
generation_status=失败 review_status=默认通过（不可用，状态映射待确认）
error_code=SOURCE_TIMEOUT retry_count=0

retry:
attempt_no=1 result=failed error_code=SOURCE_TIMEOUT
attempt_no=2 result=success generation_status=已完成 review_status=默认通过
```

`retry` 结构和错误码为新增建议，待确认；失败状态不能与默认通过并列表示可用。

## 五、用例 RPT-TC-03：飞书推送成功与失败重试

### 场景

操盘手将已完成的运营数据报告推送到一个指定飞书群；第一次因限流失败，稍后重试成功。

### 前置条件

1. 报告 `RP20260826-001` 已完成并可查看。
2. 操盘手已明确选择渠道“飞书”和目标群标识 `feishu:group-demo`。
3. 飞书 API、授权、目标权限、频率和消息格式均为待实测/待确认。

### 操作步骤

1. 创建推送任务 `PT20260826-001`。
2. 确认消息摘要包含标题、周期、摘要和详情链接。
3. 点击发送，第一次返回限流错误。
4. 查看推送任务和记录。
5. 点击失败重试，渠道返回成功。

### 预期结果

1. 推送任务只允许关联已完成报告。
2. 第一次状态为 `失败`，记录目标、摘要、发送时间（如有）、错误码和错误信息。
3. 重试保留第一次错误和尝试序号。
4. 成功后状态为 `已推送`，记录渠道返回消息 ID（若有）和发送时间。
5. 报告本体状态不回滚、不变成推送失败。
6. 成功发送不会因重复点击再次发送。

### 关键数据示例

```text
report_push_task:
task_no=PT20260826-001 report_id=RP20260826-001 channel=飞书
recipient_type=群 target_object=feishu:group-demo status=失败 retry_count=1

report_push_record attempt_no=1:
channel=飞书 target_object=feishu:group-demo
message_summary=运营数据报告｜2026-08-17至2026-08-23｜本周内容产出与互动数据汇总
sent_at=2026-08-26 10:40:00 status=失败 error_code=RATE_LIMITED

report_push_record attempt_no=2:
channel=飞书 target_object=feishu:group-demo
sent_at=2026-08-26 10:45:00 status=已推送 provider_message_id=feishu-msg-demo
```

错误码和渠道消息 ID 为新增建议，待确认；示例目标不是生产配置。

## 六、用例 RPT-TC-04：微信推送成功与失败重试

### 场景

操盘手将市场分析周报推送给指定微信目标；第一次因目标授权不足失败，调整授权后重试。

### 前置条件

1. 报告 `RP20260826-002` 已完成并默认通过可查看。
2. 用户选择渠道“微信”、目标 `wechat:user-demo`，目标类型为指定人。
3. 微信 API、授权、目标类型、频率和消息格式均待实测/待确认。

### 操作步骤

1. 创建推送任务 `PT20260826-002`。
2. 点击发送，接口返回目标授权不足。
3. 查看失败记录。
4. 修正外部授权后点击重试。
5. 查看成功记录和报告。

### 预期结果

1. 任务从待推送进入推送中，失败后进入失败。
2. 记录保存渠道微信、指定人目标、消息摘要、发送时间、状态和错误码 `TARGET_UNAUTHORIZED`。
3. 重试不新建报告，不改变报告审核状态。
4. 成功后记录 `status=已推送`、发送时间和渠道消息 ID（如可返回）。
5. 失败和成功两次尝试均可追溯。

### 关键数据示例

```text
report_push_task:
task_no=PT20260826-002 report_id=RP20260826-002 channel=微信
recipient_type=指定人 target_object=wechat:user-demo status=已推送 retry_count=1

report_push_record attempt_no=1:
channel=微信 target_object=wechat:user-demo
message_summary=市场分析周报｜2026-08-17至2026-08-23｜趋势与竞对动态
sent_at=2026-08-26 10:50:00 status=失败 error_code=TARGET_UNAUTHORIZED

report_push_record attempt_no=2:
channel=微信 target_object=wechat:user-demo
sent_at=2026-08-26 11:00:00 status=已推送 provider_message_id=wechat-msg-demo
```

## 七、用例 RPT-TC-05：报告沉淀资料库并被研究助手引用

### 场景

操盘手将市场分析周报沉淀为资料，后续研究助手引用该资料继续研究下一个主题。

### 前置条件

1. 市场分析周报 `RP20260826-002` 已完成。
2. 报告含 AI 生成的趋势和竞对结论。
3. 资料库提供一期资料分类、可信度、有效期和来源字段。

### 操作步骤

1. 在报告详情点击“沉淀到资料库”。
2. 填写资料分类“对标账号分析”或其他一期允许分类、可信度和有效期。
3. 保存资料，查看 AI 标记和报告关联。
4. 新建研究任务，选择该资料作为研究范围。
5. 在研究报告引用区域查看资料回点。

### 预期结果

1. 资料使用一期字段，不新增第二套资料口径。
2. 报告含 AI 内容时目标资料 `is_ai_product=true`。
3. 资料保留来源链接、报告 ID 和原报告引用关系；报告关联字段为新增建议，待确认。
4. 研究助手可引用该资料，研究报告仍标记 AI 产物，且不会把资料改写为原始事实。
5. 报告、资料和后续研究报告之间可追溯；具体反向关联字段待确认。

### 关键数据示例

```text
report:
report_no=RP20260826-002 report_type=市场分析周报
is_ai_product=true review_status=默认通过

material（一期字段口径）:
id=601 title=市场分析周报｜2026-08-17至2026-08-23
content=（报告正文快照）
source_type=报告 source_link=https://example.invalid/reports/RP20260826-002
credibility=中 valid_from=2026-08-26 valid_to=2026-11-26
status=已生效 is_ai_product=true
source_report_id=RP20260826-002（新增建议，待确认）

research_citation:
report_id=RR20260826-003 source_kind=material material_id=601
evidence_summary=引用周报中的竞对更新趋势（新增建议，待确认）
```
