# 数据分析_Demo_结果审核页

> 文件定位：现有 `AnalysisTaskDetail.tsx` 页面规格
> 路由：`/analysis/tasks/:id`

## 一、任务头部

- 标题：分析任务 #id：任务名称/未命名。
- 操作：返回列表、AI 原始响应、执行/重新执行、确认结果、驳回。
- 执行和审核按钮按权限及状态显示。

## 二、任务描述区

展示任务类型、状态、重试次数、创建时间、输入原始数据 Tag、提示词版本快照、资料上下文快照；失败时显示错误 Alert。

## 三、分析结果区

每个结果 Card 展示：效果、结论、建议列表、依据、资料回写状态及资料 ID、选题反哺状态及选题 ID。

任务未确认且存在结果时显示警告：必须确认后才能回写或反哺。

## 四、审核与回写交互

| 动作 | 当前条件 | 结果 |
|---|---|---|
| 确认结果 | status=待审核 + `PERM.分析结果审核` | 任务→已确认 |
| 驳回 | status=待审核 + 权限 | 任务→已废弃 |
| 回写资料库 | task=已确认 + `PERM.回写反哺` | 打开候选资料编辑 Modal，提交为 AI 待审核资料 |
| 反哺选题库 | task=已确认 + 权限 | 打开候选选题编辑 Modal，提交为待筛选选题 |
| AI 原始响应 | `has_ai_raw_response` | 打开只读 pre Modal |

## 五、回写资料 Modal

Form.List 支持多条候选；字段为标题、内容、分类、来源类型、可信度、有效期、标签。提交 POST `/analysis-results/:id/writeback-material`。

## 六、反哺选题 Modal

Form.List 支持多条候选；字段为标题、业务方向、专业方向、客户场景、用户视角、业务导向、选题原则、选题角度、核心角度。提交 POST `/analysis-results/:id/writeback-topic`。


## 八、实现差异与风险

- 页面默认使用“效果/结论/建议/依据”等 JSON 键；这些是当前通用输出展示，不代表新增固定深度指标。
- 回写资料默认来源类型“报告”、可信度“中”等是前端默认值，不是 SSOT 新规则。
- 成员审核/回写权限仍以 context/06 待确认矩阵为准。
